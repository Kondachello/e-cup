## 2. Три методические находки, касающиеся всей команды

### 2.1. `err_corr.py` меряет против устаревшего эталона

`err_corr.py` пересобирает бленд на лету из девяти захардкоженных весов; скор
этого бленда по докстрингу **1.666718**. Действующий чемпион — `blend_opt`
**1.666395** (22 члена, ridge_free lib=182, `work/reports/scores.tsv`), и именно
он лежит колонкой `blend` в `work/preds_pack/val_preds.parquet`.

Разница 0.000323 = 15 шумовых единиц. Так как `ЗАПАС = скор_бленда/скор_модели − r`,
более слабый эталон завышает запас **любой** новой модели примерно на +0.00019.

**Вопрос к треку №1:** какой эталон официальный и против какого мерился рекорд
проекта 0.00193? Если константу не обновить, приёмка систематически завышает.

### 2.2. Формула приёмки `вклад ≈ 7.1·запас²` неверна для сильных моделей

Точная алгебра парного бленда:

```
вклад = sb²·sm²·з² / [ (sm² − sb² + 2·sb·sm·з) · 2·sb ]
```

Знаменатель зависит от того, насколько модель слабее бленда. Константа 7.1
воспроизводится только при `sm/sb ≈ 1.06`:

```
sm/sb = 1.001  вклад 0.000268        sm/sb = 1.020  вклад 0.000028
sm/sb = 1.005  вклад 0.000095        sm/sb = 1.060  вклад 0.000010  <- сюда откалибровано 7.1
```

Это режим слабых моделей — февральский специалист со скором 1.83 даёт
`sm/sb = 1.098`. У трансформера `sm/sb = 1.0025`, член `(sm²−sb²)` мал, и вклад
становится почти **линейным** по запасу, а не квадратичным.

Для трансформера формула дала бы 0.000023, измеренный вклад — 0.000465,
занижение в 20 раз. В ветке `olya` записано, что формула «завышает вдвое»; знак
ошибки меняется с режимом, и это объясняет оба наблюдения. **Формулу стоит
заменить точной алгеброй** — иначе приёмка отбрасывает ровно тот класс моделей,
который план просит искать.

### 2.3. Перенос валидации на лидерборд — 40%, и причина известна

Обещано по честной OOF-оценке −0.000465, получено −0.000185. Причина не в
переобучении весов бленда (OOF это контролирует), а в **застоялости входа**:

тестовые предсказания давала модель, обученная по якорь 348, тогда как остальные
модели команды переобучены по 378. На валидации (якорь 378) у трансформера
зазор 30, как у всех, а на тесте (якорь 408) — **60 против 30**. Подпись видна
прямо в результатах: половинный масштаб выиграл у полного 7 шумовых единиц, то
есть полномасштабная добавка перелетает.

Это согласуется с находкой трека №4: застоялость входа — отдельная ось с пиком
запаса на 28–42 днях.

### 2.4. Побочно: измерен градиент по глобальному уровню

`H2_tfm` и `H2_tfm_centered` отличаются **только** константой +0.01254 в
логарифмах. Результат: 1.6489392 против 1.6489663, то есть сдвиг уровня вверх
дал −0.0000271. **Знак говорит, что глобальный уровень H1 занижен.** Замер
достался бесплатно; возможно, там лежит больше, чем весь вклад трансформера.
Это ручка трека №1, зондами.

## 3. Два бага в коде

### 3.1. `add_direction.py`: двойной логарифм

Колонки `work/preds_pack/*.parquet` **уже** в `log1p` (написано в README пакета),
а скрипт применял `L1()` к ним ещё раз. Цена: МНК по 30 моделям даёт 1.669642
вместо 1.666128, разница 0.0035 = 160 шумовых единиц.

Исправлено в `work/scripts/seq/add_direction.py`: пространство определяется
автоматически (`--pack-space auto|log|raw`). Добавлены `--center` и печать
честной оценки переноса (веса и калибровка учатся только на train-фолдах).

### 3.2. `exp_lib.py` не импортируется на Windows

`calibrate.py` → `exp_lib.py` → `import fcntl`. Модуль Unix-only, на Windows
ImportError ещё до расчёта. Чинится четырьмя строками:

```python
try:
    import fcntl
except ImportError:      # Windows
    fcntl = None
```

и двумя `if fcntl:` вокруг `flock` в `log_score()`. На Linux поведение не
меняется. **Файл общий, правку не вносил** — решение за треком №1.

## 5. Что дальше и почему именно это

Три правки, ни одна из которых не участвовала в числах выше:

1. **`--es-metric cal`** — ранняя остановка по калиброванному скору. Предсказания
   от 18.08 сделаны с остановкой по сырому. По замерам трека №1 это 0.0028 на сид.
2. **Когорта обучения по правилу трёх блоков** — прежний фильтр пускал на 10–13%
   больше слабых юзеров, чем есть в тесте.
3. **Переобучение на train+val перед предсказанием теста** — чинит застоялость
   из п. 2.3.

Чувствительность (держит `r` постоянной, поэтому оптимистична):

```
скор tfm3_cal    ЗАПАС      вклад на валидации
 1.670580      +0.00179       0.000443   (сейчас)
 1.669180      +0.00263       0.000952   (половина заявленного)
 1.667780      +0.00347       0.001654   (заявленные 0.0028)
```

Разрыв до топ-1: 1.6488111 против 1.64586 = **0.00211**.

Третья правка потребовала кода: границу обучающих якорей нельзя было задать
отдельно от валидационного, а `--val-anchor 408` невозможен — таргет берётся из
дней `якорь+1..+30`, тензор кончается на 408. Добавлены `--max-tr-anchor`,
`--fixed-steps`, `--cal-fixed`; прогон с нарушенным зазором без `--fixed-steps`
падает с явной ошибкой.

Не начато вовсе: **самообучение на неразмеченных последовательностях** —
единственный пункт задания трека, к которому не подступались.
