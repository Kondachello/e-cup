## 0. Задача в двух предложениях

По дневным логам активности 250 000 юзеров (поиски, корзины, заказы, суммы GMV — и всё,
товаров/категорий нет) надо предсказать **суммарный GMV каждого юзера за 14 фев – 15 мар 2026**.
Метрика — **RMSLE**: среднеквадратичная ошибка между `log1p(правда)` и `log1p(прогноз)`.

Ключевые следствия метрики:
- Оптимальный прогноз = `expm1( E[log1p(y)|юзер] )` — **среднее в log-пространстве**, не среднее по деньгам.
- 46% юзеров за окно не покупают вообще → таргет zero-inflated, и вся задача = «вероятность покупки × сколько в log-деньгах, если купит».

## 1. Данные и «якоря времени»

Логи: 2025-01-01 … 2026-02-13 (тест начинается сразу после конца логов).

Мы нарезаем историю на **якоря** — даты, «как будто сегодня». Для каждого якоря A:
- **фичи** юзера считаются только по данным ≤ A;
- **таргет** = его GMV за (A, A+30 дней].

Якорей ~28 (каждые 7 дней с июля-2025), плюс:
- **VAL = 2026-01-14** — главное валидационное окно (таргет 15 янв–13 фев, полностью известен);
- **VAL2 = 2025-12-31** — второе окно для проверки устойчивости;
- **TEST = 2026-02-13** — то, что заливаем на ЛБ.

## 3. Валидация: два железных правила

**Правило 1 — зазор 30 дней (`--gap-days 30`).** Для отбора моделей тренируемся только на якорях,
чьи таргет-окна закончились ДО начала валидационного окна. Иначе таргеты пересекаются и модель
«запоминает» юзеров из перекрытия — мы на этом обожглись: скоры выглядели на 0.1 лучше реальности.
(Для финального обучения под тест поздние якоря возвращаем — с тестом пересечений быть не может.)

**Правило 2 — два окна.** Каждый конфиг меряем на январском И декабрьском окнах, выбираем по среднему.
Одно окно врёт: январь аномален (новогодний обвал в фичах).

С чистым протоколом валидация совпадает с ЛБ до ~0.002 — можно верить локальным цифрам.

## 4. Модели (что в зоопарке и почему)

Все обучаются предсказывать **E[log1p(y)]** — прямо под метрику.

| Модель | Суть | Чистый val | Зачем |
|---|---|---|---|
| **hurdle-MLP** (`train_mlp2.py`) | нейросеть с двумя головами: сигмоида P(покупка) и регрессия E[log1p\|покупка]; прогноз = произведение | **1.682** (mlp2_big) | лучшая одиночная; структурно совпадает с декомпозицией метрики |
| **tweedie-on-log LGB** (`train_gbdt.py --objective log_mse --params '{"objective":"tweedie",...}'`) | LightGBM с tweedie-лоссом прямо на log1p-таргете | 1.693 (бэг из 5: **1.6925**) | лучший GBDT; tweedie-лосс хорошо переваривает массу нулей |
| **two-stage LGB** (`--objective two_stage`) | то же, что hurdle, но из двух LGB | 1.693 | GBDT-вариант hurdle-структуры |
| **прямой LGB/XGB** | обычный MSE на log1p | 1.695 | опорные, в бленд |
| **биновый MLP** (`train_mlpbin.py`) | классификация по 32 бинам log1p(y), прогноз = матожидание по softmax | в очереди | другая геометрия лосса → декорреляция |
| **ZILN-MLP** (`train_mlpziln.py`) | три головы (p, μ, σ) — zero-inflated lognormal (гуглов лосс для LTV); прогноз через квадратуру Гаусса–Эрмита | в очереди | калиброванный хвост |
| **секвенс-трансформер** (`train_seq2.py`) | по 196-дневному ряду юзера, без ручных фичей; мультитаск (y30+y7+y14+P(buy)) | 1.695/1.710 | максимум непохожести на табличные |
| **fusion** (`train_fusion.py`) | секвенс-энкодер + табличные фичи в одной сети, hurdle-головы | в очереди | кандидат в новые лучшие одиночные |
| **февральский специалист** (`train_feb_specialist.py`) | обучен на якорях фев-2025 только на фичах ≤42 дней — единственный, кто «видел» переход февраль→март с 8 марта | 1.83 соло (не страшно) | корреляция с основными всего 0.83 — сезонное знание для бленда |

## 5. Сборка: бленд → калибровка → LB-математика

1. **Бленд**: hill-climb в log1p-пространстве по валидации (`blend.py`), впереди — отбор Каруаны с бэггингом.
2. **Калибровка**: поквантильные сдвиги в log-пространстве с честной проверкой на сплите юзеров (`calibrate.py`).
3. **LB-математика — наша суперсила** (`lb_blend.py`, `work/reports/probe_design.md`):
   - Для двух файлов с известными паблик-скорами и локально вычислимым расхождением
     предсказаний **оптимальный вес смеси и её будущий скор считаются точно, без траты попыток**
     (матрица Грама ошибок). Проверено: прогноз 1.65924 → факт 1.65896; 1.65400 → 1.65360.
   - Один сабмит того же файла со сдвигом всех прогнозов на +s в log — и мы **точно знаем среднюю
     ошибку на тестовом паблике** (парабола скора). Так мы выяснили: все модели НЕДОпредсказывают
     тестовое окно (сезонность 8 марта), и вшили глобальный сдвиг +0.116.
   - **Сегментные пробы**: сдвигаем прогнозы только сегменту юзеров (например, топ-децили GMV) —
     замеряем среднюю ошибку именно этого сегмента на тесте. Уже знаем: топ-2 дециля недопредсказаны
     ещё на −0.073 сверх глобального сдвига.

## 7. Планы (в порядке исполнения)

1.
2. Ночная очередь дообучает: fusion, DART-tweedie, биновый MLP, ZILN — все с BTYD-фичами.
3. Утренний мега-бленд (Каруана по ~15 компонентам) → проба на ЛБ → его скор падает в Грам →
   **финальный микс всех измеренных файлов + сегментные коррекции**.
4. Adversarial validation (веса p(test)/p(train), отбор shift-стабильных фичей) — ветка в бленд.
5. Резерв: OOF секвенс-трансформера как фичи в LightGBM (паттерн AMEX-1st), снапшот-ансамбли нейросетей.
6. Финальные 2 сабмита: консервативный (без агрессивных коррекций) + агрессивный (с ними) — защита от шейкапа на привате (паблик всего 50k юзеров, разница 0.001 — шум).

## 8. Как это запустить у себя

```bash
python3.10 -m venv .venv && .venv/bin/pip install -r solution_lbmix2/requirements.txt lifetimes torch
# положить train.parquet и sample_submit.csv в корень
.venv/bin/python work/scripts/build_features.py --preset all      # базовые фичи
.venv/bin/python work/scripts/build_features_v2.py                # v2
.venv/bin/python work/scripts/build_features_v3.py                # v3
.venv/bin/python work/scripts/build_features_v4.py                # v4 (BTYD)
# пример обучения чемпионского GBDT (чистый протокол):
USE_V2=1 USE_V3=1 USE_V4=1 .venv/bin/python work/scripts/train_gbdt.py \
  --name my_run --model lgb --objective log_mse --gap-days 30 --n-anchors 14 \
  --params '{"objective":"tweedie","tweedie_variance_power":1.45,"n_estimators":6000}'
```

Тяжёлые обучения гоняем через файловую очередь (`work/scripts/queue_runner.py` + `enqueue.py`) —
строго по одному процессу: 16GB MacBook дважды падал от параллельных обучений, не повторяйте.

Все отчёты агентов и исследований: `work/reports/*.md` (анализ ошибок, дизайн проб, внешние техники,
adversarial validation). История скоров всех запусков: `work/reports/scores.tsv`.
