Предсказываем суммарный GMV каждого из 250 000 пользователей за 14.02–15.03.2026
по дневным логам активности (поиск, каталог, корзины, заказы; товаров и категорий в данных нет).
Метрика — RMSLE: RMSE между log1p(факт) и log1p(прогноз).

Из метрики следуют два факта, на которых построено всё решение:
1. Оптимальный прогноз — условное среднее в log-пространстве: `expm1(E[log1p(y)])`. Все модели обучаются именно на log1p-таргет.
2. 46% пользователей в окне не покупают. Задача фактически распадается на P(покупка) × E[log1p(y) | покупка].

## Структура обучающих данных

Логи покрывают 01.01.2025–13.02.2026. Из них нарезаны train-окна по cutoff-датам
(каждые 7 дней, ~28 штук): фичи считаются по данным до cutoff включительно,
таргет — GMV за следующие 30 дней после cutoff.

- Валидация: cutoff 2026-01-14 (таргет 15.01–13.02, известен полностью).
- Вторая валидация: cutoff 2025-12-31 — для проверки устойчивости.
- Тест: cutoff 2026-02-13 (таргет и есть предсказываемое окно).

## Валидация

Два правила, оба выстраданы:

1. **Зазор 30 дней между train и validation** (`--gap-days 30`). Таргет-окна train-cutoff'ов
   не должны пересекаться с валидационным окном. Без зазора таргеты общих дней попадают
   и в train, и в validation — модель частично запоминает пользователей, скор завышается
   (у нас доходило до +0.1). Для финального обучения под тест поздние cutoff'ы возвращаются
   в train — с тестовым окном пересечений нет по построению.
2. **Отбор конфигураций по двум окнам** (январь + декабрь), по среднему. Январское окно
   аномально из-за новогоднего спада и в одиночку ранжирует модели неверно.

На этом протоколе локальная валидация совпадает с public-скором до ~0.002.

## Сборка прогноза

1. Бленд моделей: взвешенное среднее в log1p-пространстве, веса подбираются на валидации (`blend.py`).
2. Калибровка: поквантильные поправки в log-пространстве с контролем на отложенной половине пользователей (`calibrate.py`).
3. Комбинирование с submission-файлами, у которых известен public-скор (`lb_blend.py`):
   ковариационная матрица ошибок двух файлов восстанавливается из их скоров и локально
   вычислимого расхождения прогнозов; оптимальные веса и итоговый скор смеси считаются
   до отправки. Проверено многократно, точность прогноза скора ~0.0005.
4. Измерения через submission'ы: повторная отправка того же файла со сдвигом прогнозов
   на константу в log-пространстве даёт точное среднее смещение на тестовом окне
   (из разности квадратов скоров). Сдвиг только на сегменте пользователей — среднее
   смещение этого сегмента. Так выяснено, что тестовое окно систематически
   недопредсказывается всеми моделями (сезонность 8 марта) — глобальная поправка
   +0.116 в log уже включена в текущий лучший submission. Детали: `work/reports/probe_design.md`.
