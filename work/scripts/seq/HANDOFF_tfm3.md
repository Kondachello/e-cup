## Но по запасу судить здесь нельзя

Правило «вклад ≈ 7.1·запас²» в этом режиме занижает в 15–20 раз. Точная алгебра
парного бленда:

```
вклад = sb²·sm²·з² / [ (sm² − sb² + 2·sb·sm·з) · 2·sb ]
```

Знаменатель зависит от того, насколько модель слабее бленда. Константа 7.1
воспроизводится при `sm/sb ≈ 1.06` — это режим слабых моделей вроде февральского
специалиста (1.83/1.666 = 1.098). У трансформера `sm/sb = 1.0025`, член
`(sm² − sb²)` мал, и вклад становится почти линейным по запасу:

```
sm/sb = 1.001  вклад 0.000268      sm/sb = 1.020  вклад 0.000028
sm/sb = 1.005  вклад 0.000095      sm/sb = 1.060  вклад 0.000010  <- сюда откалибровано 7.1
```

Измерения вместо формулы:

```
парный бленд blend+tfm3, оптимальный вес        w*=0.132   прирост  0.000149
полная переоптимизация 30 моделей + tfm3_cal,
  OOF 5 фолдов по юзерам, калибровка внутри фолда           прирост  0.000443
  (5 разных разбиений, разброс 0.000005)
плацебо: дубль случайной модели пакета, 12 повторов         прирост  0.000000
формула 7.1·запас²                                          дало бы  0.000023
```

0.000443 — это 20 шумовых единиц лидерборда (0.000022). Плацебо-контроль из
плана пройден.

В переоптимизированном бленде `tfm3_cal` получает **самый крупный вес: +0.280**.
Из 31 модели (30 в паке + tfm3) запас ненулевой только у tfm3 — остальные лежат
в оболочке по построению, они и есть базис бленда.

## Главный риск: тестовые предсказания устарели на 30 дней

В `RUN_TFM.md` это записано честно, но последствие, кажется, не оценено.
Контракт `exp_lib` требует переобучения на train+val перед предсказанием теста.
Мы этого не делали: тестовые предсказания даёт модель, обученная **по якорь 348**
(2025-12-15), тогда как остальные модели команды переобучены **по 378**.

На валидации этого не видно — там якорь 378 и обучение по 348, зазор 30, как у
всех. А на тесте (якорь 408) у всех зазор 30, а у трансформера **60**.

Значит измеренные +0.000443 на валидации — это оценка СВЕРХУ. Насколько меньше
выйдет на тесте, локально не проверить. Косвенно: в ветке olya застоялость входа
названа отдельной осью с пиком на 28–42 днях, то есть эффект не пренебрежимый.

Чинится тремя часами GPU: те же три сида с `--val-anchor 408` (обучение по 378),
`--predict` для теста. Считаю, что это надо сделать до того, как модель попадёт в
финальное решение.
