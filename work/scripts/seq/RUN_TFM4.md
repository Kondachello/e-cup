# tfm4 на GPU-машине: что запускать

Все команды здесь — одной строкой, без переносов: так они одинаково работают и в
`cmd.exe`, и в Git Bash. Перенос `^` работает только в cmd, в Git Bash он
разрывает команду и bash пытается выполнить `.py` как shell-скрипт.

Всё новое лежит в `work/scripts/seq/`: `tfm4.py`, `run_tfm4.py`, `tfm4_selftest.py`,
`tfm4_e2e.py`. `train_tcn.py` не тронут — tfm4 импортирует из него ствол, чтобы
архитектура была той же самой, а не «такой же».

## 0. Сначала самопроверка, она бесплатная

```
python work/scripts/seq/tfm4_selftest.py
python work/scripts/seq/tfm4_e2e.py
```

Обе гоняются на синтетике за пару минут и не трогают ни тензор, ни таблицу.
Если что-то из этого падает — на GPU идти незачем, сообщи мне вывод.

## 1. Кэш таблицы (один раз, ~3 минуты)

```
python work/scripts/seq/run_tfm4.py --stage prep --tab-npz from_gpu/kaggle_tabfeats_wed_v1
```

Прочитает все 26 `tabf16_*.npz`, сложит в один файл `tab_raw.f16` (~2.4 ГБ рядом
с тензором) и напечатает, какие колонки выбросил и почему. **Этот список пришли
мне** — он же уходит Александру.

В `.gitignore` дописать три строки (готовы в `gitignore_add.txt`):

```
tab_raw.*
tabstats_*.json
result_*.json
```

## 2. Проверка тёплого старта (~2 минуты, без обучения)

```
python work/scripts/seq/run_tfm4.py --stage check --seeds 1 --init-a "model_tfm2_s{seed}.pt"
```

`--init-a` — шаблон имени чекпоинта фазы A от tfm3b, `{seed}` подставляется.
**Имя почти наверняка другое**: если файла нет, скрипт напечатает список
`model_*.pt`, которые лежат рядом, — выбери оттуда и подставь.

Шаг должен закончиться строкой

```
проверка нулевой инициализации: max|Δ| = 0.000e+00
```

Ровно ноль, не «примерно». Если не ноль — прогон бессмысленный, tfm4 стартует не
из tfm3b, и сравнивать будет не с чем. Скрипт в этом случае сам падает.

## 3. Зонд: сид 1, обе ветки (~2 часа)

```
python work/scripts/seq/run_tfm4.py --stage probe --minutes 55 --seeds 1 --init-a "model_tfm2_s{seed}.pt"
```

Два прогона по 55 минут: `tfm4_a_s1` (с таблицей) и `tfm4off_a_s1` (**контроль**
— та же сетка якорей, тот же тёплый старт, таблицы нет).

Контроль не для полноты картины. tfm4 учится на 24 средах, а tfm3b учился на всех
днях подряд — 319 срезов против 24. Без контроля любой прирост нельзя отличить от
эффекта смены сетки, и число будет непроверяемым.

По правилу приёмки команды это и есть полношаговый зонд.

## 4. Смотрим, что вышло

```
python work/scripts/seq/run_tfm4.py --stage report
```

Печатает таблицу и разницу «с таблицей минус контроль». **Пришли мне её и логи
из `runlogs/`.** Дальше решаем: доливать сиды 2–3 или закрывать ось.

## 5. Если зонд положительный

```
python work/scripts/seq/run_tfm4.py --stage seeds  --minutes 55 --seeds 2 3 --init-a "..."
python work/scripts/seq/run_tfm4.py --stage phaseB --minutes 55 --seeds 1 2 3 --init-a "..." --init-b "model_tfm2_s{seed}_rt.pt"
```

Фаза B берёт число шагов и усадку из `result_tfm4_a_s{seed}.json` — то есть из
фазы A, а не подбирает заново. Иначе валидация подсматривает: в фазе B якорь 378
входит в обучение. Без `--fixed-steps` скрипт запускаться отказывается.

Тёплый старт строго A←A, B←B. `--init-b` — чекпоинт tfm3b, переученный по 378.

## Сколько это стоит по времени

```
prep                    ~3 мин
check                   ~2 мин
probe (сид 1, 2 ветки)  ~2 ч
сиды 2-3 (4 прогона)    ~4 ч
фаза B (3 сида)         ~3 ч
```

В восемь часов целиком не влезает. Порядок выбран так, чтобы после первых двух с
небольшим часов уже было понятно, стоит ли тратить остальные шесть.

## Что перезапуск не сломает

Очередь пропускает готовое: если `result_<тег>.json` есть и выгрузка ровно на
250000 строк — шаг не повторяется. Выгрузка не на 250000 строк считается
**незаконченной** и прогоняется заново (тот самый случай с 40000 строк, который
чуть не уехал в четвёртый трек).

Прогон, который упал, не останавливает очередь — остальные идут дальше, код
возврата в конце ненулевой, подробности в `runlogs/`.

## Полезные флаги, если понадобятся

```
--tab-lr-mult 0.3     табличной ветке меньший learning rate, если ствол просядет
--tab-warmup 3000     первые N шагов учить без таблицы
--tab-drop-drift 2.0  выбросить колонки, чьё среднее на val/test уехало > 2 sd
--min-anchor-day 250  не брать ранние якоря, где истории мало
--tab-ram             держать таблицу в RAM (+2.4 ГБ), если memmap тормозит
```

Все по умолчанию выключены: по умолчанию идёт ровно то, что описано в брифе.

## На что смотреть в логе

Каждая оценка печатает две метрики:

```
step  10000  loss 0.9  val RMSLE 1.6712  без таблицы 1.6801 (Δ -0.0089)
```

`без таблицы` — это `score_tabzero` из брифа: та же сеть с отключённой табличной
веткой. Если это число начнёт **расти** относительно первой оценки больше чем на
0.02, в строке появится `<- СТВОЛ ПРОСЕЛ`: значит ветка перетянула на себя, а
последовательностная часть деградировала. Это ровно тот сценарий, ради которого
Александр просил collapse-проверку.
