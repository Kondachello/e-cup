## Главный вывод, из-за которого меняется план

**Зондировать оси, измеримые на валидации, экономически невыгодно.**

Вывод в одну строку. Ось с валидационным выигрышем `G` даёт при применении доли `c`
тестовый выигрыш `(2cκ − c²)·G`. Тогда:

| решение | E[выигрыш] |
|---|---|
| применить по приору (`c = m = 0.333`), **попытка не тратится** | `m²·G = 0.111·G` |
| сначала зондировать, потом применить (`c = m + w(κ̂−m)`) | `(m² + w·τ²)·G = 0.123·G` |
| **чистая ценность зонда** | **`w·τ²·G = 0.0116·G`** |

Зонд добавляет **1.2%** выигрыша оси, а простое применение даёт **11.1%** — в десять раз
больше и бесплатно. Причина в части A: `w = τ²/(τ²+SE²) = 0.28`, то есть замер κ настолько
шумный, что почти не двигает апостериор.

**Отсюда дихотомия, на которой строится весь бюджет:**

- **Тип L** — ось измерима локально (есть `G` на валидации). **Не зондировать.**
  Применять по приору класса, попытку не тратить.
- **Тип S** — оси на валидации не существует (структурное свойство тестового окна:
  сезонность, отбор, календарь). Замер — единственный путь, ценность зонда = весь выигрыш.

## Порог для зонда типа S

Выигрыш направления `k²·q` при `q = 0.0002`, усадка `a = max(0, 1 − SE²/k̂²)`:

| ожидаемая k | E[выигрыш] после усадки | сигм в замере |
|---|---|---|
| 1.0 | 0.000180 | 3.0 |
| 0.8 | 0.000109 | 2.4 |
| 0.6 | 0.000055 | 1.8 |
| 0.5 | 0.000035 | 1.5 |
| **0.4** | **0.000019** | 1.2 |
| 0.3 | 0.000008 | 0.9 |

**Порог: зондировать, только если ожидаемая |k| ≥ 0.33** (одна сигма). Ниже — усадка
съедает больше половины, и ожидание падает под уровень шума 0.000022.

## Цена применения оси

Каждое подобранное направление добавляет **0.000022** фиктивного выигрыша на паблике
(их же замер, `noise_floor.py`). Это прямая цена: на привате она испаряется.

**Правило приёмки для трат: применять ось, только если E[тестовый выигрыш] > 0.000022.**
Это втрое ниже прежнего порога 0.0003 — потому что порог 0.0003 отвечал на другой
вопрос («стоит ли строить»), а этот на вопрос «стоит ли применять уже построенное».

**Следствие, важное для планирования: связывающее ограничение — не попытки, а
переобучение под паблик.** Попыток 55, осмысленных действий — единицы. Применение
двадцати маргинальных направлений добавит 0.00044 переоценки паблика при разрыве
до топ-1 0.0031.

## Правило остановки

Прекратить тратить попытки, когда выполнено любое из:

1. лучшая ожидаемая ценность зонда < **0.000022**;
2. свободных попыток осталось **3** (резерв);
3. накопленная переоценка паблика превысила **0.0005** (это ~23 применённых
   направления; сейчас ~8 = 0.0002);
4. наступило 29.08 — дальше только сборка и замер финалистов.

## Выбор двух финалов

Оба слота дают приватный скор, в зачёт идёт лучший. Ценность второго слота равна
`E[max(X₁,X₂)] − E[X₁] = σ_d/√π = 0.564·σ_d`, где `σ_d` — разброс РАЗНИЦЫ приватных
скоров двух кандидатов.

Ключевое: `σ_d` определяется не SE скора (0.0028), а **непохожестью кандидатов**.
Два файла с корреляцией направлений 0.999 дают `σ_d ≈ 0.0002` и ценность второго
слота `0.0001` — почти ноль.

**Правило:**

1. **Финал 1 — измеренный.** Лучший файл с ПОДТВЕРЖДЁННЫМ публичным скором. Гарантия.
2. **Финал 2 — берётся, только если** его направление отличается от первого с
   корреляцией < 0.999. Иначе второй слот потрачен впустую, и правильнее взять
   вторым файл, отличающийся СТРУКТУРНО (например, без цепочки поправок), даже если
   он хуже по паблику: он страхует от ошибки сборки, а не от шума.
3. **Оба обязаны иметь замеренный публичный скор** — файл без замера проверить нечем.
4. Ручной выбор до 12:00 31.08 обязателен: иначе платформа возьмёт два лучших по
   пабликy, а они почти наверняка окажутся почти одинаковыми (см. п.2).

Считалка печатает `σ_d` в сигмах приватного при подстановке разницы кандидатов.

## Как пользоваться считалкой

```bash
python work/zhenya_eda/scripts/budget.py --demo
python work/zhenya_eda/scripts/budget.py --state work/zhenya_eda/state.json
```

Формат состояния:

```json
{"today": "2026-08-20", "best_measured": 1.648093, "finalists_measured": 1,
 "line_improving": true, "delta_between_candidates": 0.0003,
 "axes": [
   {"name": "tfm3b", "type": "L", "cls": "history_model", "mdl_corund": 0.00090},
   {"name": "сезонный хвост", "type": "S", "q": 0.0002, "k_expect": 0.6}
 ]}
```

`type`: `L` — ось измерима на валидации, `S` — только на лидерборде.
`cls` — класс для приора κ: `history_model` 0.90, `probe_applied` 0.85,
`blend_delta` 0.56, `feature_stack` 0.20, `level` 0.15, `segment` 0.05.
`G` — валидационный выигрыш оси (если бы κ=1), в RMSLE.
`k_expect` — ожидаемая доля для структурной оси.

Выход: ранжированный список действий с E[выигрыш] и ценой в попытках, резерв,
правило остановки и арифметика второго слота.

## Что в этом расчёте слабое

- Приор `m = 0.333` и разброс `τ = 0.205` оценены по десяти точкам, у которых
  собственная SE 0.332. Приор класса надёжнее общего, но и он на 1–2 точках.
- Ценность зонда `w·τ²·G` предполагает, что κ и G независимы. Если оси с большим G
  систематически лучше переносятся, зонд стоит дороже расчётного.
- Порог 0.000022 взят из их замера фиктивного выигрыша; он относится к одному
  подобранному направлению, а не к применению уже замеренного коэффициента.
