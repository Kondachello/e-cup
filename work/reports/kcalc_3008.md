## 1. Блок A. Уровень: что перебрал и почему не сошлось

### 1.1 Машинка

`Λ = diag(q·(1−w)·τ²)` при `w = τ²/(τ²+σ²)` обращается точно:

    h = Λ_ii/q_i   =>   w_i = h/σ_i²  ,  τ_i² = h σ_i²/(σ_i² − h)

Проверено на `gls_state_a2.npz`, где `w` и `tau` записаны явно: расхождение
**1.4e-15** и **2.8e-15**. Значит из одной Λ каждого состояния восстанавливается
весь его приор поосно, и все маршруты считаются для всех 35 состояний.

Контроли, на которых машинка проверена (все сошлись **точно**):
паблик-алгебра всех 26 состояний (`base` 1.6457652, `f12` 1.6456258, `a3g0` 1.6456098,
`int08` 1.6454950, `extctl` 1.6455987, `extebz` 1.6453830); солверный `E[priv]−F7`
из `eb_decomp` §5 и §5.3 (15.30 / 14.69 / 17.16 / 19.76 / 20.31 / 22.57 шума);
`Σ_ε` и `Σ_p` из `V` (`K` совпадает с записанным `Kdiag` до 8e-16); единица
штаба выведена из алгебры: `0.8·F/50000 = 2.6334e-5` (штаб 2.63e-5),
`1.25·ед = 3.2917e-5` (штаб PER 3.294e-5); маршруты R2c на старом приоре
(A 37.005, B 16.231, C 23.030, D 19.19, E 23.24) — совпали с `a6_k_link.json`.

### 1.2 Твой след: приращение поймано γ, не приором

| | tr[(Q+Λ+γ·diagQ)⁻¹Q] |
|---|---|
| F8-группа, γ=0.10 (её собственная) | **37.0051** |
| f12, γ=0.08 (её собственная) | **37.9671** |
| a3g0, γ=0.00 (её собственная) | **44.4755** |
| f12 при γ=0.10 | 36.8410 |
| a3g0 при γ=0.10 | 36.8047 |
| F8 при γ=0.08 | 38.1484 |
| F8 при γ=0.00 | 44.8753 |

При общей γ = 0.10 приращения: F8→f12 **−0.164**, F8→a3g0 **−0.200**.
Весь «+0.962» — это переход γ 0.10→0.08 (+1.143), весь «+7.47» — переход
γ 0.10→0.00 (+7.87). След движется в СТОРОНУ, ОБРАТНУЮ приору: Λ_ii = q·τ²σ²/(τ²+σ²)
РАСТЁТ с τ (это диагональ апостериорной дисперсии, `Λ = diag(V_star)/q`), поэтому
широкий приор даёт БОЛЬШЕ демпфирования в этом следе, а не меньше. Формула
«приорная часть без гребня» уровень не достраивает: она вообще не растёт с приором.

### 1.3 Перебор определений

Перебраны 20 функционалов × 17 подмножеств осей (семьи `model`/`segment`/`decomp`,
их объединения, Z-имена, отсечки по `w` и по `q`): следы `tr[(Q+Λ)⁻¹Q]`,
`tr[(Q+Λ+γdQ)⁻¹Q]`, `tr[(Q+γdQ)⁻¹Q]`, их диагональные версии, `tr H`, `tr(2H−H²)`,
`tr[Q⁻¹Λ]`, `n − tr[Q⁻¹Λ]`, `Σw`, `Σ(1.25w−0.25)`, `Σw²`, `Σ(2w−w²)`, `Σ(1−w)`,
`1.25·trK − 0.25n`, `tr[(Q+Λ)⁻¹Σ_ε]/u`, версии со свободным уровнем (−1) и с
множителями 1.25/−0.25.

**Лучшее без подгонки — промах 0.71 направления** (`Σ(1.25w−0.25)` на подмножестве
«q ниже медианы» — подмножество бессмысленное, найдено перебором). Ни одно
осмысленное подмножество не даёт лучше 1.9.

**Аффинная проверка** (калибруем `k = a + b·f` по ДВУМ точкам base и a3g0, третью
точку f12 предсказываем): лучший промах 0.14 направления, снова на дредженном
подмножестве; на всех семейных подмножествах промах 0.25…2.1. Две константы на
две точки с одной проверкой — доказательной силы не имеет.

### 1.4 Почему не сходится: доказательство, а не перебор

`f12` отличается от `a3g0` ТОЛЬКО сужением сегментного приора: 0.141 → 0.0575/0.106/0.112,
**все 21 ось сужаются**. Любой df-функционал монотонен по ширине приора поосно,
значит обязан дать `k(f12) < k(a3g0)` с зазором не меньше честного сегментного
слагаемого. Реестр требует зазор ровно `11.27 − 9.30 = 1.97`. Честный зазор
**3.517**. Разнесение осей по подгруппам не «неизвестно» — оно записано в Λ:

| подгруппа | осей | вклад в дифференциал |
|---|---|---|
| τ_seg = 0.112 | 9 | −0.835 |
| τ_seg = 0.106 | 7 | −0.977 |
| τ_seg = 0.0575 | 5 | −1.706 |
| **итого** | **21** | **−3.517** |
| гипотетически все 21 на 0.112 | — | **−1.981** ← это и есть реестровые «−1.98» |
| гипотетически все 21 на 0.0575 | — | **−8.557** ← это реестровые «−8.56» |

Реестровый интервал «−1.98 … −8.56» воспроизведён с точностью до второго знака как
**супремум и инфимум по равномерному разнесению**. Ни одна естественная подгруппа
(молчащие seg_jasper/seg_garnet/seg_realgr: −1.259; seg_nickel/seg_opal/seg_chalk: −0.307; seg_zircon…seg_gneiss: −2.252) на −1.98 не
попадает. **Три реестровых числа — это не три значения одной величины, а замер,
дифференциал и граница.**

### 1.5 Что вместо уровня: маршрут C, анкерованный собственной контрподписью

`k = 1.25·trK − 0.25·n`, `K = Σ_p(Σ_p+Σ_ε)⁻¹` — γ-свободен, значит согласован с
признаком сравнимости (проверено: внутри каждой из 20 групп значение совпадает
побитово). `Σ_ε` восстанавливается из `V` каждого состояния (`K = I − V·Σ_p⁻¹`);
на `a2`, где `Σ_ε` записана явно, два пути совпадают до **3.6e-15**.

Маршрут C — тот самый, что назван в воротах-4, и на F8 он даёт **23.03**, ровно как
в `r2c_countersign_f8.md`. Считаю его основным для УРОВНЯ и оставляю реестровый
дифференциальный счёт для СРАВНЕНИЙ.

## 3. Блок B. k(F12) = 7.76, и граница здесь работает против нас

**Верно 7.76.** Реестровые 9.30 неверны по названной в самом реестре причине:
«неизвестно, какая ось попала в какую подгруппу». Это было верно на момент записи,
но `gls_state_f12.npz` разнесение содержит: из Λ поосно восстанавливаются
τ_seg = 0.0575 (5 осей), 0.106 (7), 0.112 (9), и точный дифференциал **−3.5171**
(§1.4). Итог: **k(F12) = 8.30 + 2.9724 − 3.5171 = 7.755**. Расхождение с реестром
**1.54 направления = 5.07e-5 = 2.3 шума**.

**Верхняя граница в формуле со штрафом — консервативно или нет: ответ двойной.**

* Для **абсолютной** оценки нашей позиции — консервативно. Завышенное k завышает
  E[priv] нашего файла, то есть занижает наши шансы. Здесь мы округляли безопасно.
* Для **сравнения наших файлов между собой — НАОБОРОТ, и мы округляли в опасную
  сторону.** Кандидату k считается своим счётом, а действующему F12 подставлялась
  граница. Каждый претендент, чей приор НЕ содержит сегментного расщепления,
  получал **1.54 бесплатных направления = 2.3 шума** форы.

Кого это затронуло в каталоге A5: `ebz362`, `ebz209`, `f10g08/10`, `mom`, `reml`,
`t35`, `zhM`, `base`, и — что важнее всего — **`a3g0`, то есть наш действующий слот-2**.
Кого НЕ затронуло: `int08`, `int10`, `seg4`, `seg4eb` — у них то же расщепление,
что у F12 (проверено поимённо: счётчики τ_seg 9/7/5 совпадают), и подпорка
сокращается в разности. Поэтому колонки каталога по `int*` остаются верными,
а по остальным — сдвинуты в пользу претендента.

**Что это меняет для действующей пары.** Отставание F13_g0 от F12 в приватной
валюте считалось как Δpub + PER·(11.27 − 9.30) = 4.14 шума. Правильно
Δpub + PER·(11.27 − 7.755) = **6.45 шума**. Лотерейный билет слота-2 дешевле,
чем считалось, на 2.3 шума. Решение это не меняет (F13_g0 замерен, ближайшая
альтернатива не замерена), но P(топ-3) пары **завышена** и подлежит пересчёту

## 4. Блок C. Множитель ×2.4: подтверждён на 46 осях, ОПРОВЕРГНУТ как универсальный

### 4.1 Подтверждение двумя своими маршрутами

Требуемый Δk считаю как `(Δpriv − Δpub)/PER`, где Δpriv — честная апостериорно

| точка | Δpub, ш | Δpriv, ш | Δk треб. | Δk **routeD** | ×routeD | Δk **routeB** | ×routeB |
|---|---|---|---|---|---|---|---|
| `ebz209` против F8 | −5.89 | −0.57 | 3.554 | 1.485 | **×2.39** | 1.650 | ×2.15 |
| `ebz362` против F8 | −13.13 | +1.43 | 9.723 | 4.073 | **×2.39** | 4.049 | ×2.40 |

«route D диагонален и не видит связи через Грам» **не работает**: разрыв переживает
полный счёт.

### 4.2 Опровержение универсальности: третья точка, 84 оси с капами

Та же правка τ_z 0.0148 → 0.0209 на живой 84-осевой системе (`extctl` → `extebz`,

| точка | Δpub, ш | Δpriv, ш | Δk треб. | Δk routeD | множитель |

### 4.3 Оговорка о природе множителя

Множитель — это НЕ обязательно «недосчитанные направления». Строка @0.0209 в
перекрёстной таблице §5.1 при истинной τ = 0.0148 даёт 14.39 против 15.30 у F8, то
есть кандидат ПРОИГРЫВАЕТ 0.91 шума, если реестровая τ верна. Заметная часть
разрыва — это **риск того, что расширение просто неверно**, а не переобучение.
На решение это не влияет (обе компоненты вычитаются из ожидания кандидата), но
называть весь множитель «k» строго говоря нельзя.

### 4.4 EB-гиперпараметры сегментного расщепления: оценка

`eb_segment.md` §2 даёт число прямо: тест отношения правдоподобий пул → 4 подгруппы
идёт с **df = 6** (4 μ + 4 τ минус 1 μ + 1 τ пула). Верхняя граница вклада в k —
**+6 направлений** (по калибровке R2c одна свободно подогнанная по паблику ось даёт
ровно k = 1); реалистично меньше, потому что расщепление хорошо идентифицировано
(перестановочный тест p = 0.0003, 36 точек κ̂ на 6 параметров).

**Куда это входит и куда не входит:**

* Группы G12 (`f12`, `seg4eb`), G13 (`int08`, `int10`), G16 (`seg4`) имеют **одно и
  то же** расщепление 9/7/5 — слагаемое у них общее и **в разности F12 ↔ int08
  сокращается точно**. Порядок этой пары от него не зависит.
* Против F12 играют все ПУЛОВЫЕ группы (G0, G1, G6, G7, G11, G14, G15, G18, G19,
  все 84-осевые): у них этого слагаемого нет, значит k(F12) занижен относительно них
  на величину до +6, и претенденты получают до **6·PER = 1.98e-4 = 9.0 шума** форы,
  не показанной ни в одной таблице. Это самая крупная непокрытая величина в блоке A,
  и знак её — против F12, то есть в пользу `ext*` и `ebz*`. Счёт по верхнему краю:
  +6 направлений = 8.98 шума форы. `ebz362` (+8.22) и `f10g0*` (+6.19/+6.63) при
  этом выходят в небольшой плюс; `ext283` — нет, ему нужно **11.5…11.9 направлений**,
  то есть вдвое больше верхнего края. Оговорка: у `ext*` и `ebz*` есть свои
  EB-гиперпараметры (τ_z, а у `ext*` ещё и τ_model), так что «фора» им достаётся
  не целиком; чистой она была бы только для `base`/`a3g0`, у которых оба приора
  реестровые.
* EB-гиперпараметры Z-семейства (μ_z, τ_z, 30 осей, ДИ95 фактор 6.7 — идентификация
  слабая, вклад близок к полным +2) отдельно НЕ добавляю: замеренный множитель
  ×2.39 получен сквозным счётом ровно на этом переходе и их уже содержит.
  Складывать нельзя — будет двойной счёт.

### 5.2 Три независимых счёта по `int08` сходятся

Два самых прямых пути сходятся на **+0.6…0.7 шума в пользу `int08`**, и это лучшее,

я не выяснил.

**Множитель, при котором преимущество `int08` исчезает на route D: ×2.71**
(замерено ×2.39). Запас по множителю **13 %**.

правка названа паблик-смещённой на голой 46-осевой системе.

### 5.3 Почему 84-осевые не проходят и что здесь остаётся спорным

`ext283` даёт −20.4 шума паблика — больше всех. Чтобы это окупилось, нужно
k(ext283) < 21.4. Дифференциал route D от якоря даёт 32.9, маршрут C — 54.6.
Единственное соглашение, дающее меньше 21.4, — пропорциональное пересчитывание
уровня (`k = 8.30/19.18 · routeD = 18.9`), а его `r2c_countersign_f8.md` §7 прямо
отвергает: «все проверки двигают k только ВВЕРХ, ни одна не вниз».

**Что остаётся честно спорным.** Солверная валюта и валюта штаба по 84-осевым файлам
расходятся на ~46 шумов на одном и том же файле. Перекрёстная таблица под ОБЩИМ
c_Q (я её посчитал в 84-мерном вложении; 84-осевая Q содержит 46-осевую точно,
расхождение 1.7e-14) даёт `extctl` **19.28** шума против `base` **9.01** и `f12`
**7.31** — то есть по солверу 84-осевые файлы лучше вдвое. Валюта штаба говорит
обратное. Это ровно нерешённый спор ворот-4, и решить его за оставшееся время
нельзя. **Ставка на `ext283` — это ставка на солверную валюту против штабной.**

Оговорка в пользу осторожности: `f12` и `int08` в этой таблице оцениваются под
c_Q, которые сегментного расщепления НЕ содержат (84-осевых прогонов с расщеплением
нет), то есть под допущением, что их собственная правка неверна. Их 7.31 и 6.72
занижены. Насколько — не считал.
