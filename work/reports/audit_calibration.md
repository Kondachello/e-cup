## БАГ 1 — направление поквантильной калибровки: НЕ ПОДТВЕРЖДЁН

### По коду

`work/scripts/calibrate.py:24-39`. `fit_shifts` бьёт **прогноз** `lp` на
квантильные бины и внутри каждого бина считает
`shift = mean(ly[bin]) - mean(lp[bin])`; `apply_shifts` возвращает
`lp + interp(shift)`. Это в точности биннированная оценка **E[ly | lp]** —
регрессия факта на прогноз, то есть правильное направление (аналог
изотонической калибровки, только с линейной интерполяцией сдвига вместо
монотонной подгонки). Отображения маргинального распределения прогнозов на
маргинальное распределение таргета в коде нет нигде.

Тот же `fit_shifts`/`apply_shifts` переиспользуется поканальной калибровкой
`train_channel.py:108-145` (`*_chcal`) — направление то же, плюс отдельный
глобальный множитель Йенсена `k` в линейном пространстве.

## БАГ 2 — разрыв Йенсена в hurdle/ZILN: НЕ ПОДТВЕРЖДЁН

### По коду — все три семейства выдают E[log1p(y)]

**`train_mlp2.py` (двухголовая hurdle).** Голова `head_mu` учится MSE только на
положительных строках по цели `ylog = log1p(y)` (строка 159:
`mse = F.mse_loss(mu[pos], yb[pos])`), то есть `mu ≈ E[log1p(y) | y>0]`. Прогноз
(строка 126): `pred_log = sigmoid(logit) * clamp(mu, min=0)`. Так как
`log1p(y) = 0` при `y = 0`, произведение — это ровно
`P(y>0) · E[log1p y | y>0] = E[log1p y]`. Дальше `expm1` только для хранения в
рублёвой шкале, а `rmsle` снова берёт `log1p` — round-trip, ничего не теряется.

**`train_mlpziln.py` (ZILN).** Строки 129-158: `E[log1p(y)] = sigmoid(logit) ·
E[softplus(Z)]`, `Z ~ N(mu, sigma²)`, интеграл берётся 20-точечной квадратурой
Гаусса-Эрмита. Так как `Z = log(y)`, то `softplus(Z) = log1p(y)` тождественно.
Это **не** каноническая ZILN-формула `E[y] = p·exp(mu+sigma²/2)` — она осознанно
заменена на E[log1p], что и требуется для RMSLE. Потери на `log(y)`, прогноз на
`log1p(y)` — согласовано.

**`train_gbdt.py` (чемпион-бустинг).** Здесь была реальная развилка, проверил
отдельно. Флаг `--objective tweedie` (строки 223-224, 230) ставит `y = y_raw` и
отдаёт `pv = clip(raw_pv, 0)` — это **и есть** E[рублей], и с ним RMSLE берёт
`log1p(E[y])`, то есть баг Йенсена. Но чемпионский рецепт этот путь не
использует, он вызывается как

```
train_gbdt.py --objective log_mse --params '{"objective":"tweedie","tweedie_variance_power":1.45,...}'
```

(`README.md:54,132`). Ветка `log_mse` ставит `y = np.log1p(y_raw)` (строка 212),
а `--params` подменяют только внутреннюю функцию потерь LightGBM. Девианс
Твиди — дивергенция Брэгмана, её популяционный минимум = условное среднее цели,
поэтому прогноз = **Ê[log1p(y) | x]**. `scores.tsv` это подтверждает: все
`twl*`/`c_twlog*` записаны как `lgb/log_mse`, `c_ts2_*` как `lgb/two_stage`
(там `p · clip(mu,0)`, тоже корректно). **Ни одна модель в бленде не
логарифмирует матожидание рублей.**

## БАГ 3 — обрезание в ноль: НЕ ПОДТВЕРЖДЁН

### Где стоит clip

1. **Внутри моделей.** У `mlp2` прогноз `sigmoid(logit) · clamp(mu, min=0) ≥ 0`
   по построению; у `mlpziln` — `p · E[softplus(Z)] > 0` по построению; у
   `two_stage` — `p · clip(mu, 0)`. То есть внешний `clip(pred_log, 0, None)`
   там **тождественно не срабатывает**. Реально обрезать может только ветка
   `log_mse` GBDT (`raw_pv + m_hat` не ограничен снизу).
2. **В калибровке** — `calibrate.py:39` `clip(lp + adj, 0, None)`.
3. **В бленде/сабмите** — `assemble_final.py` клипает при чтении каждого файла и
   при записи.

### Структурный аргумент

`ly = log1p(y) ≥ 0` тождественно, потому что `y ≥ 0`. Значит
`|max(lp,0) − ly| ≤ |lp − ly|` поточечно для любого `lp`: обрезание — проекция
на допустимое множество, оно **не может увеличить** ошибку ни на одном объекте.
«Смещение вверх», которого опасалось исследование, существует
(`E[max(lp,0)] ≥ E[lp]`), но оно неустранимо при неотрицательном таргете и
покупается строгим уменьшением поточечной ошибки. Экспериментальное
подтверждение: `postproc_sweep.py` гонял семейство `zero_floor` (обрезание в
ноль по порогу t ∈ [0.1, 3.0]) — оптимум t = 0 в каждом фолде, любое t > 0
ухудшает (`work/reports/postproc_sweep.md`).

**Вердикт: бага нет.** Доля обрезаемых значений ≤ 0.08 % (у большинства моделей
ровно 0), влияние на средний остаток нижних 20 % ≤ 0.0002, на RMSLE — ноль до
6-го знака.

## Дополнительно: оптимальный глобальный сдвиг b* = mean(ly) − mean(lp)

`gain` — in-sample выигрыш RMSLE `√MSE − √(MSE − b*²)`; `honest gain` — честный
2-fold (сдвиг фитится на половине пользователей, меряется на другой, обе
стороны усреднены); `affine` — то же для полного `a + b·lp`.

| модель | RMSLE | **b\*** | RMSLE со сдвигом | gain | honest gain | honest affine |

Сдвиг b* = −0.0247, подобранный на окне 15 янв — 13 фев, — это оценка

порога применения 0.0008 из того же протокола, так что вопрос академический.

## Что реально стоит сделать (побочные находки, а не баги)

1. **`caruana_v1` не откалиброван.** slope = 1.0239 — единственная модель с
   заметной **недо**дисперсией (ей нужно растяжение, а не усадка), b\* = −0.0158.
   Честный 2-fold выигрыш от биннированной калибровки **+0.001298**, от полного
   affine +0.000512. Выше порога применения 0.0008. Оговорка: веса caruana
   подбирались на всех val-пользователях, а библиотека включала до-gap30
   `xgblog_final`/`lgblog_final` (solo 1.630/1.633), поэтому 2-fold по
   пользователям для неё не полностью честен — перепроверить на отложенном
   якоре, прежде чем шить в сабмит.
2. **`CLEAN` в `assemble_final.py:29-31` смешивает калиброванные и сырые
   модели.** Координатный спуск в лог-пространстве нормирует веса в сумму 1, так
   что бленд наследует взвешенное среднее уровневых смещений компонент; сейчас
   спасает только доминирующий вес `mlpbin_cal` (0.895). Прогнать `calibrate.py`
   по сырым участникам (`twl_repair_ab`, `twl_v7`, `c_ts2_s42`, `c_twlog_s42`,
   `c_xtw_s42`, `twdeep`, `fusion`, `seq2tr_f`, `whale_final`, `behavonly`,
   `febspec`) перед бленд-поиском — дёшево и уже проверено out-of-fold
   (1.6927 → 1.6695 на `twl_repair_ab`, 1.6931 → 1.6685 на `c_ts2_s42`). Та же
   оговорка: калибровка на VAL шьёт в модель сезонный уровень января, поэтому на
   тесте выиграет только форменная часть.
3. **Ветка `--objective tweedie` в `train_gbdt.py:223-224,230`** — минное поле
   (+0.68 RMSLE при случайном вызове). Убрать из `choices` или добавить явный
   варнинг.
