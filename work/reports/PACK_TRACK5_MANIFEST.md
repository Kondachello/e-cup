# Пакет трека 5 (последовательные модели): что внутри и как это порождается

Сопровождает `pack_track5.tgz` — 88 файлов, 114 МБ. Собран 27.08 для пакета
жюри. Цель — показать, что код порождает те самые два члена бленда, а не что
веса воспроизводятся побитово.

## Что дал бленду трек 5

Два члена, принятых 25.08 после независимой проверки треком 4:

| член | запас | вклад | что это |
|---|---|---|---|
| `tfm4_cal` | +0.00162 | 0.000521 | событийный трансформер + 176 табличных колонок |
| `tfm4_tabless_cal` | **+0.00439** | 0.000456 | тот же ствол с обнулённым входом таблицы |

Запас ствола +0.00439 — рекорд проекта (прежний 0.00307 у `lagd28`). Честный
кросс-фит пары: **+0.000641** (`joint_gain.py`, веса бленд 0.646 / tfm4 0.277 /
tabless 0.079). `tfm3b` этой парой поглощён: в наборе с ней его вес ровно 0.000.

## Единственная вещь, которую надо знать про файлы весов

**Отдельного чекпойнта `tfm4_tabless` не существует, и это не пропажа.** Ствол
без таблицы — та же самая сеть, у которой обнулён вход табличной ветки.
`TabFusion.forward_both` считает оба ответа за один проход ствола:

```python
z0 = self.base.neck.mlp[0](self.pool(x))
return self._heads(z0 + self.mix(self.act(self.emb(tab)))), self._heads(z0)
```

Поэтому на конфиг идёт **один** файл весов `model_tfm4_<фаза>_s<сид>.pt`, а
`*_tabless_*.parquet` — второй выход того же прогона. Искать вторые веса не надо.

## Как это порождается

```
python work/scripts/seq/run_tfm4.py --stage prep   --tab-npz <каталог tabf16_*.npz>
python work/scripts/seq/run_tfm4.py --stage probe  --minutes 55 --seeds 1   --init-a "model_tfm2_s{seed}.pt"
python work/scripts/seq/run_tfm4.py --stage seeds  --minutes 55 --seeds 2 3 --init-a "model_tfm2_s{seed}.pt"
python work/scripts/seq/run_tfm4.py --stage phaseB --minutes 55 --seeds 1 2 3 \
       --init-a "model_tfm2_s{seed}.pt" --init-b "model_tfm2_s{seed}_rt.pt"
```

Подробности и флаги — `RUN_TFM4.md`. Вход: тензор последовательностей и кэш
таблицы `tab_raw.f16` (собирается стадией `prep` из 26 матриц `tabf16_*.npz`).

## Дисциплина, проверяемая кодом

- **Зазор фазы A — 35 дней**, и это не заявление: `tfm4.py:513` считает
  `gap = VAL - max(grid)` и падает с `SystemExit`, если зазор меньше горизонта
  таргета (30). Каждый лог печатает
  `якорей обучения 24 (182..343), валидация 378, тест 408, зазор 35 дней`.
- **Фаза B ничего не переподбирает.** Число шагов и обе усадки берутся из
  `result_tfm4_a_s<сид>.json`; без `--fixed-steps`, `--cal-fixed` и
  `--cal-fixed-tabless` фаза B отказывается стартовать. Это важно, потому что
  валидационный якорь 378 входит в её обучение — печатаемый там `val RMSLE`
  показателем не является.
- **Тёплый старт побитово нейтрален.** Табличная ветка инициализируется нулём,
  и каждый прогон печатает `проверка нулевой инициализации: max|Δ| = 0.000e+00`
  — на старте tfm4 тождественно равен tfm3b, иначе прогон не начинается.
