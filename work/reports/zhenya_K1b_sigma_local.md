# K1b: локальная σ_u — замкнутая форма, и почему мой blanket ×1.15 был неверен

---

## Короткий ответ

**Мой blanket-множитель 1.15 неверен для сегментных осей.** Он был замерен на
**модельных разностях** (tfm4, gru, ridge, shade) — плотных направлениях,
сосредоточенных на юзерах с большой ошибкой. Сегментные индикаторные оси —
другое дело: у большинства из них множитель **меньше единицы**.

Множитель считается **точно, локально и без единой посылки**:

```
g² = σ_u²/(F0²·q) = ((1−p)·A + p·B) / (p·A + (1−p)·B)

p — доля юзеров в сегменте
A — MSE ВНУТРИ сегмента,  B — MSE СНАРУЖИ
```

Для малого сегмента `g² → A/B`. То есть **g определяется тем, какую долю ошибки
несёт сегмент**, и это одна строка кода на валидации.


---

## 1. Вывод

Среднесохраняющая индикаторная ось сегмента S с долей p:
`h_i = 1{i∈S} − p` (с точностью до масштаба).

```
q = mean(h²) = p(1−p)
σ_u² = Var(h·r) ≈ E[(1_S−p)²·r²] = p(1−p)·[(1−p)A + pB]
F0² = p·A + (1−p)·B
```

откуда `g² = σ_u²/(F0²q) = ((1−p)A + pB)/(pA + (1−p)B)`.

Смысл прозрачный: **если сегмент несёт непропорционально много ошибки (A > B),
замер по нему шумнее, чем говорит формула `F0√q`; если мало — точнее.**

## 2. Проверка на настоящих данных

Валидационное окно, модель на якоре 14.01.2026 (`v1_erafix.npz`), F0 = 1.6720.
Сегменты восстановлены из `train.parquet` теми же правилами, что у зондов.

| сегмент | p | доля MSE | A/F0² | B/F0² | g (формула) | g (прямо) |
|---|---|---|---|---|---|---|
| топ-5 % активных | 0.050 | 0.032 | 0.629 | 1.020 | 0.805 | 0.805 |
| свежие 0–14 | 0.382 | 0.390 | 1.019 | 0.988 | 1.004 | 1.004 |

Колонка «прямо» — это `sd(h·r)/(F0·√q)`, посчитанное в лоб. **Совпадает с формулой
до третьего знака на всех шести сегментах** — вывод верен.

Диапазон **0.67 … 1.05**, а не 1.15. Механизм очевиден задним числом:
никогда-не-покупавшие предсказуемо не покупают, у них маленький остаток, значит
индикатор на них даёт **точный** замер, а не шумный.

## 3. Поправка к моей вчерашней доктрине

Вчера в K1 §2 я записал в реестр `σ = 1.15·F0/√(nq)·√(1−f)` как общее правило.
**Это верно только для модельных разностей и неверно для сегментных осей.**
Оба моих вчерашних пути измеряли именно модельные разности:

- прямая симуляция — оси tfm4/gru/ridge/shade, то есть разности предсказаний
  моделей: они сосредоточены на активных юзерах с большой ошибкой → g > 1;
- семейство Z-разложения — тоже разности членов бленда, та же природа.

Правильная запись:

| тип оси | g |
|---|---|
| разность моделей / членов бленда | **≈ 1.15** (замерено, 1.12–1.62) |
| сегментная индикаторная | **считать по формуле §1**, диапазон 0.67–1.05 |
| прочие структурные | считать по формуле, `σ_u = sd(h·r)` локально |

**Общее правило, которое надо было записать сразу: σ_u считается локально как
`sd(h·(t − lp))` на валидации, а `F0·√q` — это грубая аппроксимация, верная лишь
при независимости направления от остатка.**

## 6. Что нужно от тебя — одна строка кода

Для каждой оси, где я поставил g наугад, посчитай на валидации:

```python
p = mask.mean()
A = (r[mask]**2).mean()          # r = предсказание − таргет на ВАЛИДАЦИИ
B = (r[~mask]**2).mean()
g = math.sqrt(((1-p)*A + p*B) / (p*A + (1-p)*B))
```

и подставь в `σ = g · 0.894 · F0/√(n_пуб·q)`. Нужны **seg_dolom (промо-наклон),
seg_chalk (промо), seg_verdit (горячие корзины)**. Три числа закрывают вопрос окончательно.

Если под рукой нет валидационных остатков — сойдёт любая приличная модель на
якоре 14.01.2026; g устойчив к качеству базы, потому что это **отношение** MSE,
а не абсолютная величина.

## 7. Оговорки

- g замерен на валидационном окне; на тестовом структура остатка может отличаться.
  Но механизм структурный (никогда-не-покупавшие предсказуемо не покупают), так
  что знак и порядок переносятся. Точность — не лучше ±0.05.
- Формула выведена для **индикаторных среднесохраняющих** осей. Для непрерывных
  направлений (наклоны, градиенты) она не годится — там `σ_u = sd(h·r)` считать
  напрямую, без замкнутой формы.
- Приращение F7 посчитано в предположении, что дозы F6 поставлены при g = 1.
  Если ты уже применял к части осей 1.15, приращение будет больше.
