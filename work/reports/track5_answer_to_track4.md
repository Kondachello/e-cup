## Ещё одно, к вопросу о формуле вклада

Вы применяете точную формулу с поправкой 0.75 на кросс-фит — это правильно, и
наши измерения с этим согласуются. Отмечу для протокола: правило «вклад ≈
7.1·запас²» в режиме сильных моделей занижает **в 15–20 раз**. Знаменатель
точной формулы зависит от того, насколько модель слабее бленда:

```
вклад = sb²·sm²·з² / [ (sm² − sb² + 2·sb·sm·з) · 2·sb ]
```

Константа 7.1 воспроизводится при `sm/sb ≈ 1.06` — режим слабых моделей вроде
февральского специалиста (1.83/1.666 = 1.098). У tfm3 `sm/sb = 1.0025`, член
`(sm² − sb²)` мал, и вклад становится почти **линейным** по запасу:

```
sm/sb = 1.001  вклад 0.000268      sm/sb = 1.020  вклад 0.000028
sm/sb = 1.005  вклад 0.000095      sm/sb = 1.060  вклад 0.000010  <- сюда откалибровано 7.1
```

Это объясняет, почему в ветке olya формула «завышает вдвое» на слабых моделях,
а у нас занижает на сильных: знак ошибки меняется с режимом.

Наши измерения вместо формулы (эталон `blend_opt` 1.666395):

```
парный бленд blend+tfm3, оптимальный вес w*=0.132            0.000149
полная переоптимизация 30 моделей + tfm3_cal, OOF 5 фолдов
  по юзерам, калибровка внутри фолда                         0.000443  (разброс 0.000005)
плацебо: дубль случайной модели пакета, 12 повторов          0.000000
формула 7.1·запас²                                           0.000023
```

# Вопрос 2: инференс с ранних якорей

## Делаем. Но в предложенных командах три ошибки, каждая валит прогон

**1. `--eval_only` не существует.** Флаг называется `--eval-only`. Argparse не
сопоставляет подчёркивание с дефисом.

**2. Аргументы архитектуры обязательны.** `build_model` берёт
`channels/layers/heads/dropout` из аргументов командной строки, а не из
чекпойнта:

```python
if arch == 'transformer': return Transformer(n_in, a.channels, a.layers, a.dropout, a.heads)
```

По умолчанию `--channels 128`, а у нас 192 — `load_state_dict` упадёт на
несовпадении размерностей. Нужно `--channels 192 --layers 4 --heads 4
--dropout 0.0`.

**3. Маска якоря отрезает часть юзеров — вы получили бы не 250000 строк.**
Это вы знать не могли, деталь наша:

```python
val_u = torch.arange(st.n_u)[st.valid[:, VAL_ANCHOR]]
```

На якоре 378 маску `valid_anchor` проходят все 250000, а на раннем — нет: на
2025-09-15 проходило 0.9086, на 2025-11-15 — 0.9326. Добавили флаг
**`--val-all`**, который маску обходит.

Плюс `TEST_ANCHOR` теперь флаг **`--test-anchor`**, константу на строке 22
править не надо.

## Границы обучения совпали с вашей таблицей ровно

| сторона | чекпойнт | граница обучения | якорь инференса | запас | застоялость |
|---|---|---|---|---|---|
| val | фаза A `model_tfm2_sN.pt` | 348 | **350** | 2 дн | **28 дн** |
| test | фаза B `model_tfm2_sN_rt.pt` | 378 | **380** | 2 дн | **28 дн** |

Утечки в окно оценки нет: обучающие якоря фазы A ≤ 348, их таргеты кончаются
на дне 378, а меряется окно 379–408.

Скрипт теперь сам отказывается работать, если якорь инференса попадает в
обучающий диапазон:

```
якорь val 348 не больше границы обучения фазы A (348): это утечка. Максимум --stale 29
```

## Как это запускается у нас

```powershell
python work\scripts\seq\run_all.py --data tensor --stale 28
```

Раннер берёт нужные чекпойнты, проставляет якоря 350 и 380, прогоняет три сида
на каждой стороне, усредняет их в лог-пространстве и кладёт результат.

Если захотите воспроизвести на своих чекпойнтах — команда одного прогона:

```powershell
python work\scripts\seq\train_tcn.py --data tensor --arch transformer `
  --channels 192 --layers 4 --heads 4 --dropout 0.0 --batch 512 --ema 0.995 `
  --eval-only --ckpt model_tfm2_s1.pt --val-anchor 350 --val-all `
  --cal-fixed 0.95 --export work\preds --tag tfm2_s1_stale28 --no-plots
```


**Ловушка, которую мы изолировали.** Тестовая сторона считается чекпойнтом
фазы B, обученным по 378, поэтому его val-выгрузка с якоря 350 лежит **внутри**
его обучения. Такие файлы переименовываются в `*.LEAKY_DO_NOT_USE`. Если будете
запускать руками — не берите val-выгрузку с чекпойнта фазы B.
