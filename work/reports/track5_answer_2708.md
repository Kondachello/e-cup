## 2. Вторая половина дисциплины: фаза B ничего не переподбирает

Валидационный якорь 378 входит в обучение фазы B, поэтому любой подбор по нему
был бы утечкой. Он и невозможен:

- число шагов и усадка берутся из `result_tfm4_a_s<сид>.json`, то есть из фазы A
  (`run_tfm4.py`, стадия `phaseB`);
- `tfm4.py` отказывается запускать фазу B без `--fixed-steps` и `--cal-fixed`
  (`SystemExit` до загрузки тензора);
- усадка ствола без таблицы тоже фиксируется из фазы A — без
  `--cal-fixed-tabless` фаза B не стартует. Эта проверка стоит первой строкой
  `main()` намеренно: раньше она была в конце и прогон падал бы через 55 минут.

Проверить по фактам: в `result_tfm4_b_s{1,2,3}.json` поля `best_step` и `cal`
совпадают с одноимёнными в `result_tfm4_a_s{1,2,3}.json` (14000/0.93, 18000/0.95,
18000/0.93).

Как построены, в пространстве log1p:

```
T1 = G2 + 0.90 · d(tfm4)
T2 = G2 + 0.45 · d(tfm4)
T3 = T2 + 1.18211 · (G2 − V3)          # доза оси G с 0.20 до 0.4364
```

Множитель 1.18211 получен из параболы оси G по двум замеренным точкам
(κ = 0.436423, Q = 0.00049651); подстановка воспроизводит оба исходных замера
с точностью 0.0e+00. Оси практически ортогональны: корреляция направления G с
направлением tfm4 внутри T2 равна −0.023, поэтому вклады складываются.

## 4. σ_d: независимое подтверждение замера Оли

Трек 5 замерил σ_d своим способом, не зная про `final_pair_memo.md`.

- Схема та же по смыслу: юзеры фиксированы (250000 валидации), случаен только
  раскол на приват 200k и публику 50k.
- Калибровка на 160 парах, непохожесть sd(разности) от 0.0024 до 0.75.
- Результат: **σ_d = 0.001114 · sd(разности в log1p)**, R² = 0.976. На подвыборке
  только мелких различий (sd < 0.05) коэффициент 0.001123 — закон линеен на всём
  диапазоне.

У Оли `σ_d = 0.0011 · rms`. Совпадение до третьего знака на разных наборах пар.
Вывод тот же: дисперсионная ценность второго слота ниже шума замера при любом
разумном кандидате, слот идёт как страховка от ошибки сборки.

## 5. Для пакета жюри: отдельного чекпойнта «tabless» не существует

В задании 3 просят «чекпойнты боевых tfm4/tfm4_tabless». Файлов два разных не
будет, и это не потеря: ствол без таблицы — **та же самая сеть**, у которой
обнулён вход табличной ветки. `TabFusion.forward_both` считает оба ответа за
один проход ствола:

```python
z0 = self.base.neck.mlp[0](self.pool(x))
return self._heads(z0 + self.mix(self.act(self.emb(tab)))), self._heads(z0)
```

То есть на конфиг идёт один файл весов `model_tfm4_<фаза>_s<сид>.pt`, а
`*_tabless_*.parquet` — это второй выход того же прогона. В сопроводиловке
пакета так и стоит написать, иначе будет поиск несуществующих файлов.

## 7. Две правки в коде трека 5 после ночи 25.08

- **Загрузчик переживает нехватку ОЗУ.** При `DefaultCPUAllocator: not enough
  memory` поток раньше молча умирал, а `get()` блокировался на `q.get()` без
  таймаута — прогон вис навсегда. Теперь поток ждёт 0.25 с и повторяет; если
  умирают все, `get()` через 30 с падает с текстом. Ночь 25.08 из-за старого
  поведения потеряла фазы B.
- **`run_tfm4.py --no-ctrl`.** Контрольная ветка `--tab-off` больше не гоняется
  по умолчанию в стадии `seeds`: вопрос равной ёмкости закрыт зондом сида 1, а к
  бленду контроль ничего не добавляет (ствол+joint G = +0.000859, с контролем
  +0.000856). Экономит 55 минут на конфиг.
