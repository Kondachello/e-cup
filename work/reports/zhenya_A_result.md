## 1. Механизм

Из разложения таргета `lp = μ + s + ε` (доли 0.392 / 0.196 / 0.412 на валидационном
окне, λ=0.8486) ошибка модели на окне t раскладывается как `e_t = b − δ_t − ε_t`:
`b` — смещение на юзере (одинаково в обоих окнах), `δ` — неотфильтрованная медленная
часть (автокоррелирована с λ), `ε` — белый шум окна.

Ковариация оси с ошибкой распадается по тем же каналам, и при шаге ровно в одно
30-дневное окно (val 15.01–13.02 → test 14.02–15.03):

```
κ = β + λ·σ ,      β + σ + ν = 1 ,      λ = 0.8486
```

Предельные случаи, которые формула обязана давать и даёт:
ось чинит юзерское смещение → κ=1; ось подогнана под остаток валидации → κ=0;
ось эксплуатирует фазу → κ=λ=0.85.

**Почему обычная теория переобучения тут не работает.** Поправка `k·σ²/n` при
n=250 000 и σ²=2.777 даёт для k=1 завышение 1.11e-5 против сигнала 0.001 (MSE) —
то есть κ должна была бы быть 0.99. Наблюдаются 0.0–0.6. **Перенос ломает подгонка
под ОКНО, а не под юзеров: юзеров 250 тысяч, а окно одно.** Разрез по пользователям
от этого не защищает по построению — то же семейство, что провал моего скрининга
представлений и ловушка caruana.

### Честная оговорка, без которой числа выше не значат ничего

Доли β/σ/ν по классам я назначал **уже видя замеры** — они лежали в одной таблице.
Девять суждений на девять точек: это подгонка, и MAE 0.095 к валидации отношения
не имеет. Засчитывать требование по этому числу нельзя.

Что честно выводится из механизма ДО всяких чисел — это **порядок**: чем больше
доля построения оси пришлась на подгонку под валидационное окно, тем меньше κ.
Порядок `проба > бленд > уровень ≈ стек > сегмент > своп` следует из конструкции
осей, а не из их замеров, и он подтверждается (+0.86).

**Единственная законная проверка** — приложить κ_pred к осям, ещё не замеренным.
Предсказания на заявленные оси даны в §5, они датированы этим отчётом.

## 3. Ошибка замера κ = 0.332

Установлена тремя независимыми способами:

| способ | значение |
|---|---|
| пять проб из `probes_5.md`: k делить на сигмы | 0.319 / 0.324 / 0.329 / 0.331 / 0.335 → **0.328** |
| их же рецепт усадки `a = max(0, 1 − 0.11/k²)`: 0.11 = SE² | **0.332** |
| мой прямой расчёт SE коэффициента оси на 50k публики (`k2_kappa_se.py`) | 0.11–1.4 в зависимости от оси |

Третий способ даёт разброс, потому что SE зависит от геометрии оси:
`SE(c) = sd(e·h)/(√n·mean(h²))`. Для осей с большим `|c_val|` (стек, ступенька)
относительная SE мала; для осей с крошечным `|c_val|` (уровень, крошки, дельта
одной модели) она превышает единицу — оттуда и берутся κ=1.12 и κ=−0.20.

**Следствие 1.** Точки с малым `|c_val|` неинформативны в принципе. Крошки (1.12)
и своп (−0.20) — это не «плохой перенос», а деление на почти ноль.

**Следствие 2, для части B.** Одиночный замер κ — слабый инструмент. При априорном
разбросе κ между осями τ ≤ 0.205 (оценён как избыточная дисперсия сверх шума) и
ошибке замера 0.332 оптимальная усадка:

```
w = τ² / (τ² + SE²) = 0.042 / (0.042 + 0.110) = 0.28
κ̂_итог = 0.28 · κ_замер + 0.72 · κ_приор_класса
```

**Свежезамеренной κ верить на 28%, остальное брать из приора класса.**

## 4. Что НЕ получилось: зеркальный оценщик

Замысел (`k1_kappa_mirror.py`): мерить κ на двух исторических окнах, где ответ
известен, и не тратить попытки. Реализация **дала нестабильные числа**: для дельты
пересборки бленда −0.500 / +0.552 / +3.526 по трём парам окон.

Диагноз честный: (а) мой «бленд» из трёх сидов одного конфига вырожден, корреляция
прогнозов 0.999, поэтому переподбор весов ловит шум, и направление — почти чистый
шум; (б) для осей с малым `c1` отношение `c2/c1` взрывается ровно по механизму §3.

Чинится это пулом с настоящим разнообразием (нужны прогнозы разных семейств на
исторических якорях, у меня их нет — в пакете только val и test). **Если дадите
предикты 3–5 непохожих моделей на 2–3 исторических якорях, зеркало заработает
и даст κ без траты попыток.** Это самая полезная вещь, которую я мог бы доделать.

## 5. Предсказания на незамеренные оси (датированы, для честной проверки)

По механизму `κ = β + λσ`, доли назначены по конструкции оси:

| ось | конструкция | β/σ/ν | **κ_pred** | 80%-интервал |
|---|---|---|---|---|
| tfm3b (секвенсная модель) | обучена на истории, вала не видела | 0.75/0.20/0.05 | **0.92** | 0.75–1.00 |
| kevf | если это признаковый стек — подгонка под вал | 0.10/0.15/0.75 | **0.23** | 0.05–0.45 |
| joint-fusion (пересборка набора) | веса под окно + реальное улучшение | 0.35/0.25/0.40 | **0.56** | 0.35–0.75 |

Правило для любой новой оси в одну строку:

```
κ_pred = β + 0.849·σ,  где
  β = доля выигрыша, объяснимая улучшением прогноза НА ЮЗЕРЕ
      (модель обучена на истории, вала не видела)
  σ = доля, объяснимая лучшей оценкой текущей фазы юзера
  ν = доля, полученная подгонкой под валидационное окно (веса, пороги,
      посегментные поправки, любые коэффициенты, увиденные на вале)
```

Практическая эвристика: **ν ≈ доля свободных параметров, подобранных на валидации,
от всей конструкции оси.** Модель, обученная только на исторических срезах, имеет
ν≈0 и κ≈0.9. Ось, целиком подогнанная под остаток вала, имеет ν=1 и κ≈0.

## 6. Вердикт по требованию

- Механизм выведен и объясняет порядок (+0.86, p=0.003) — **сделано**.
- MAE 0.095 получена, но **не засчитываю**: подгонка при видимых мишенях.
- Честная валидация вынесена вперёд: три датированных предсказания в §5.
- Доказательство непредсказуемости **не получилось** и не требуется: κ предсказуема
  по классу, но не по отдельному замеру, потому что сам замер имеет SE 0.332.
- Главный практический выход не формула, а **правило усадки 0.28/0.72** и понимание,
  что осям с малым `|c_val|` замер κ вообще противопоказан.
