## 1. Лоссы/архитектуры для zero-inflated heavy-tail регрессии (ZILN и др.)

**Источники**
- Wang, Liu, Miao (Google), «A Deep Probabilistic Model for Customer Lifetime Value Prediction» — https://arxiv.org/abs/1912.07753 (pdf: https://arxiv.org/pdf/1912.07753)
- Официальная реализация (Keras, репо заархивировано апр. 2026, код доступен): https://github.com/google/lifetime_value ; community-обёртка: https://github.com/Willofd101/ziln_cltv
- Tweedie GBDT для экстремально несбалансированных нулей: https://arxiv.org/pdf/1811.10192 ; Zero-Inflated Tweedie boosted trees (CatBoost): https://arxiv.org/pdf/2406.16206
- Сравнение ZILN/Tweedie/гибрид ZIT (Aalto thesis, полный текст отдаёт 403, видно из индексации): https://aaltodoc.aalto.fi/bitstreams/99065e1d-a917-4da6-80ee-605bdd00117c/download
- Focal loss (классификационная голова): https://www.abhik.ai/concepts/losses/focal-loss ; Delving into Deep Imbalanced Regression (Focal-R, LDS/FDS для хвоста): https://arxiv.org/pdf/2102.09554

**Суть.** ZILN = смесь точечной массы в нуле и логнормали. Три головы от общего транка: `p_logit` (sigmoid), `mu` (linear), `sigma` (softplus с нижним клипом). Лосс = BCE(p, 1{y>0}) + 1{y>0}·NLL логнормали по (mu, sigma). В статье vs MSE: +11.4% относительных на дискриминации покупки и на порядок лучшая калибровка по децилям. Insurance-литература: чистый Tweedie недооценивает долю нулей при сильной инфляции; ZI-обёртка или ZILN калиброваннее на тяжёлом хвосте.

**Ключевая математика под нашу метрику (главная находка направления).** Статья предсказывает E[Y] = p·exp(mu+sigma²/2) — это НЕ оптимум для RMSLE. Оптимальная точка под RMSLE — E[log1p(Y)]. При Y|Y>0 ~ LogNormal(mu, sigma²): log1p(Y) = softplus(Z), Z = log Y ~ N(mu, sigma²), значит

E[log1p(Y)] = p · (1/√π) · Σᵢ wᵢ · softplus(mu + √2·sigma·xᵢ)  — 20-точечная квадратура Гаусса–Эрмита, копеечная по CPU.

Наш hurdle-MLP уже даёт p·E[log1p|покупка], но точечной регрессией без sigma. Замена регрессионной головы на (mu, sigma) с логнормальным NLL даёт: (а) правильное матожидание через квадратуру (softplus выпуклый ⇒ point-head систематически смещён на юзерах с высокой дисперсией — ровно наш болевой сегмент «умеренно активных»); (б) per-user sigma как вход посегментной/поквантильной калибровки (шринкаж высокодисперсных предсказаний), которую мы считали исчерпанной — но она исчерпана без признака неопределённости.

**Focal.** При 46% нулей дисбаланс мягкий; focal с gamma 0.5–1.0 на BCE-голове — микровыигрыш, зато LDS (label distribution smoothing) из DIR-статьи на хвосте E[log1p|покупка] — осмысленный кандидат, если хвостовые юзеры недоучены.

**Применимость/сложность.** Улучшает лучшую одиночную модель (hurdle-MLP): смена головы + лосса + инференс-квадратура ≈ 3–5 ч на M1 (одно переобучение MLP, в очередь). Ожидание: +0.001–0.003.

## 2. Self-supervised / pretraining для секвенсов активности

**Источники**
- PatchTST (ICLR 2023): https://arxiv.org/abs/2211.14730 ; HF-порт с PatchTSTForPretraining: https://huggingface.co/docs/transformers/en/model_doc/patchtst
- TS2Vec (AAAI 2022, иерархический contrastive, дешёвый): https://github.com/zhihanyue/ts2vec , https://ojs.aaai.org/index.php/AAAI/article/view/20881
- PTUM — masked behavior + next-K behaviors претрейн юзер-моделей: https://arxiv.org/pdf/2010.01494
- Bootstrapping your behavior (BYOL-стиль, без негативов): https://arxiv.org/abs/2506.11053
- Abacus — претрейн, выровненный на РАСПРЕДЕЛЕНИЯ СЧЁТЧИКОВ событий, для sequential user modeling в рекламе: https://arxiv.org/abs/2512.16581 (гибрид счётчики+секвенс, до +6.1% AUC даунстрим)
- SHORE (долгосрочный LTV в играх): https://arxiv.org/pdf/2506.10487 ; обзор TS-претрейна: https://arxiv.org/pdf/2305.10716

**Суть.** Masked-patch реконструкция (PatchTST) стабильно бьёт supervised-обучение с нуля и переносится между датасетами; PTUM/Abacus подтверждают ровно наш случай — агрегированные дневные счётчики поведения, а не item-последовательности (BERT4Rec-стиль по товарам нам недоступен и не нужен). Abacus — ближайший аналог: claim, что цели, согласованные со счётчиками, лучше голой masked-реконструкции.

**Применимость.** У нас 250k юзеров × 409 дней БЕЗ меток — претрейн можно гнать по всем дням, а не по 28 якорям: (1) masked-day/masked-patch реконструкция 8-канальных векторов; (2) pretext «предскажи сумму GMV следующего окна» на произвольных псевдо-якорях (это synthetic-надзор из самих логов — по сути тысячи якорей вместо 28). Затем fine-tune двух голов. Главная ценность НЕ в +скор самого трансформера, а в декорреляции: у нас все модели скоррелированы 0.98+, и претрейненный на другом сигнале трансформер — единственный реалистичный путь получить модель с другой структурой ошибки для бленда.

**Сложность на M1 Pro 16GB.** PatchTST-масштаб (~1М параметров, 196×8, патч 16/страйд 8 ≈ 24 токена) — претрейн 1 эпоха по 250k×сотни псевдо-якорей это часы; одно обучение). Риск средний. Ожидание: одиночный трансформер +0.002–0.005, вклад в бленд +0.001–0.002.

## 3. Ковариатный сдвиг train-якоря vs тестовый якорь (Jan/Mar, 8 марта)

**Источники**
- Практика adversarial validation: https://medium.com/@sumantabasak/adversarial-validation-what-is-it-why-is-it-important-9445667522dc ; https://medium.com/@nlztrk/adversarial-validation-a-sanity-checker-and-an-exploiter-2dff1baced19 (403 на fetch, рецепты видны из индексации); курс-конспект: https://apxml.com/courses/monitoring-managing-ml-models-production/chapter-2-advanced-drift-detection/adversarial-validation-drift
- Боевое применение в соревновании: ShareChat RecSys Challenge 2023, LightGBM + adversarial validation для выкидывания дрейфующих фич: https://arxiv.org/abs/2310.03778
- Взвешивание вместо выкидывания (веса p/(1-p)): https://medium.com/@frederico.nogueira/weighted-adversarial-validation-part-1-the-theory-af2b9e1f7f23 ; кейс кредитного скоринга (когда дропать, когда взвешивать): https://arxiv.org/pdf/2112.10078
- Recency/сезонные веса сэмплов в ритейл-прогнозах: https://jackbakerds.com/posts/upweight-recent-observations-regression-classification/ ; M5-разборы: https://medium.com/artefact-engineering-and-data-science/sales-forecasting-in-retail-what-we-learned-from-the-m5-competition-445c5911e2f6 , https://phdinds-aim.github.io/time_series_handbook/08_WinningestMethods/lightgbm_m5_forecasting.html ; Favorita-валидация окном, совпадающим с тестом: https://arxiv.org/pdf/2009.07701 («Learnings from Kaggle's Forecasting Competitions»)

**Суть/рецепт.** (1) LGBM-классификатор «строка train-якоря vs строка тест-якоря» на наших 200 фичах, 5-fold, смотрим AUC. AUC≫0.5 гарантирован (сезонная позиция якоря различима). (2) Итеративно дропаем топ по adversarial-importance, пока AUC не упадёт к ~0.5–0.6; переобучаем боевые модели на стабильном подмножестве — так делал Uber в проде и ShareChat-победители. (3) Альтернатива дропу, когда фича и дрейфует, и предсказывает: sample_weight = p_test/(1−p_test) с капом. (4) Валидационные якоря выбирать по максимальному p_test — «валидация, похожая на тест».

**Сезонный джекпот (проверить немедленно).** 409 дней истории от ~13 фев 2026 назад накрывают ЯНВАРЬ 2025 — значит, в логах ЕСТЬ 14 фев – 15 мар 2025, включая 8 марта 2025, ВМЕСТЕ с дневными суммами GMV. Отсюда два хода, не требующих внешних данных:
- **Якорь-сезонный аналог**: якорь 14.02.2025 с таргетом = сумма дневного GMV юзера за 14.02–15.03.2025 (таргет вычислим из самих логов). Lookback у него усечён (~44 дня) — окна капнуть по доступности + missing-индикатор. Валидировать финальный бленд на нём и/или апвейтить его при обучении.
- **Фичи «праздничной аффинности» юзера**: отношение GMV/корзин юзера в окне 22.02–08.03.2025 к его базовому уровню; счётчики активности в гендерные праздники прошлого года. Тестовое окно накрывает тот же праздник — модель впервые получит прямой сигнал, кто именно раскупается к 8 марта. Ошибка сконцентрирована в «умеренно активных» — праздничные покупатели-подарочники как раз там.

**Применимость/сложность.** Бьёт точно в установленный Jan/Mar-сдвиг, работает для GBDT без всякой доменной адаптации. Adversarial-прогон + отбор фич: 2–4 ч. Праздничные фичи + сезонный якорь: ~3 ч инженерии + одно переобучение GBDT в очередь. Ожидание: +0.002–0.006 суммарно (самое большое отношение выигрыш/риск из всех направлений); побочный бонус — модель на стабильном подмножестве фич автоматически декоррелирована для бленда.

## 4. Ансамблирование при корреляции 0.98+

**Источники**
- MLWave Kaggle Ensembling Guide (rank averaging, геометрические средние, weighted majority): https://mlwave.com/kaggle-ensembling-guide/
- Power/geometric ensembling для скоррелированных моделей (Laurae): https://medium.com/data-design/reaching-the-depths-of-power-geometric-ensembling-when-targeting-the-auc-metric-2f356ea3250e
- Caruana, Ensemble Selection from Libraries of Models (ICML'04) + bagged-вариант: https://www.cs.cornell.edu/~alexn/papers/shotgun.icml04.revised.rev2.pdf ; https://dl.acm.org/doi/abs/10.1007/978-3-642-35101-3_59
- Hill climbing с отрицательными весами, готовый модуль: https://github.com/Matt-OP/hillclimbers (параметр negative_weights; 4-е место Kaggle PSS S3E14); https://www.kaggle.com/code/slythe/post-ensembling-hill-climbing-weighted-scipy

**Суть/вердикт.** Для RMSLE арифметика в log1p-пространстве уже эквивалентна геометрическому среднему в raw — мы это делаем; rank averaging для scale-чувствительной метрики требует обратного квантильного маппинга и на корреляции 0.98 даёт ~0. Отрицательные веса в hill-climb умеют вытаскивать крошечные комплементарные компоненты, но на OOF люто оверфитят — обязателен bagged-вариант Каруаны (случайные подбиблиотеки моделей + сэмплирование с возвращением, усреднение весов по бэгам). Консенсус Kaggle-практики: при r=0.98+ и residual-R²≈0 линейный бленд исчерпан математически; выигрыш добывается НЕ формулой смешивания, а изготовлением разнообразия выше по течению — разные подмножества фич (стабильное подмножество из напр. 3!), разные подмножества якорей, разные таргет-трансформации (log1p vs √log1p vs hurdle-бинаризация), сиды. Это единственный честный ответ направления: №4 сам по себе не приоритет, он дожимает результат направлений 1–3.

**Сложность.** Bagged hill-climb с negative_weights поверх расширенной библиотеки: ~2 ч CPU-лёгко. Ожидание: +0.000–0.002.
