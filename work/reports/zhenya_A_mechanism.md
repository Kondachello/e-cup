# Часть A: механизм переноса val→LB. Вывод

Женя, 20.08.2026. Черновик вывода; численная валидация — ниже по мере счёта.

## 1. Определение

Ось — направление `h` (вектор по юзерам в лог-пространстве), прибавляемое к прогнозу:
`pred' = pred + c·h`. Оптимальные коэффициенты:

```
c_val  = -<e_val , h> / ||h||²      (подобран на валидации, 250k)
c_test = -<e_test, h> / ||h||²      (реализовался на тесте, замер LB на 50k)
κ      = c_test / c_val
```

Замечание о форме: если κ определять по ВЫИГРЫШУ, а не по коэффициенту, то
`κ_gain = κ(2−κ)`. Это меняет числа: κ=0.5 даёт κ_gain=0.75, κ=1.12 даёт 0.986.
Ниже всё в терминах коэффициента; при сверке с Олей формы надо согласовать.

## 2. Разложение ошибки

Из моего разложения дисперсии таргета (на валидационном окне):
`lp_u,t = μ_u + s_u,t + ε_u,t`, доли **0.392 / 0.196 / 0.412**, `λ = 0.8486` за 30 дней.

Прогноз модели забирает μ целиком и часть s. Значит ошибка на окне t:

```
e_u,t = b_u − δ_u,t − ε_u,t
   b_u    — систематическое смещение модели на юзере: СВОЙСТВО ЮЗЕРА, одинаково в обоих окнах
   δ_u,t  — неотфильтрованный остаток медленной компоненты: автокоррелирован с λ
   ε_u,t  — белый шум окна: между окнами независим
```

## 3. Ключевое тождество

Ковариация оси с ошибкой распадается по тем же трём каналам:

```
<h, e_val>  = <h,b> − <h,δ_val> − <h,ε_val>
<h, e_test> = <h,b> − <h,δ_test> − <h,ε_test>
```

Подставляем `E<h,δ_test> = λ·<h,δ_val>` (шаг ровно в одно 30-дневное окно:
val 15.01–13.02 → test 14.02–15.03) и `E<h,ε_test> = 0` (белый шум, а h подобрана
на валидации, поэтому с ε_test не связана):

```
             <h,b> + λ·(−<h,δ_val>)
κ  =  ────────────────────────────────────────
       <h,b> + (−<h,δ_val>) + (−<h,ε_val>)
```

Обозначим доли валидационного выравнивания по каналам: β (юзерская), σ (медленная),
ν (шумовая), β+σ+ν = 1. Тогда

```
        ┌──────────────────┐
        │   κ = β + λ·σ    │        λ = 0.8486
        └──────────────────┘
```

Формула читается прямо: **переносится ровно то, что является свойством ЮЗЕРА
(целиком) и свойством МЕДЛЕННОЙ компоненты (с коэффициентом λ); всё, что ось
подцепила из шума валидационного окна, не переносится вовсе.**

Предельные случаи, которые формула обязана давать:
- ось чинит систематическое смещение модели на юзере (β=1) → κ=1;
- ось подогнана под остаток валидации (ν=1) → κ=0;
- ось эксплуатирует фазу (σ=1) → κ=λ=0.85.

## 4. Почему обычная теория переобучения тут НЕ работает

Стандартная поправка на подгонку k параметров по n наблюдениям даёт завышение
`k·σ²/n`. При n=250 000 и σ²=2.777 это `k·1.11e-5` в единицах MSE. Выигрыш 0.0003
RMSLE это 0.001 MSE, значит для k=1 отношение завышения к сигналу 0.011 — то есть
κ должна была бы быть 0.99. Наблюдаются 0.0–0.6.

**Вывод: перенос ломает не переобучение по ЮЗЕРАМ, а подгонка под ОКНО.** Юзеров
250 тысяч, а окно — одно. Кросс-проверка по пользователям от этого не защищает по
построению (это ровно то, что записано в KNOWLEDGE:741 про библиотеку из 188 моделей
и в моём же провале со скринингом представлений).

Отсюда практическое: **ν нельзя оценить разрезом по юзерам, его можно оценить только
вторым ОКНОМ.**

## 5. Как считать β, σ, ν, не тратя попытку

Прямое следствие §3: κ оценивается зеркалом на исторических окнах. Берём два якоря
A1, A2 с НЕпересекающимися целевыми окнами, разнесёнными ровно на 30 дней (та же
геометрия, что val→test), строим ось по рецепту её класса на A1 и меряем, какая доля
её выравнивания дожила до A2:

```
κ̂ = <h_A2, e_A2> / <h_A1, e_A1> · ||h_A1||² / ||h_A2||²
```

Это НЕ регрессия по свойствам оси, а прямой замер того же механизма на данных,
где ответ известен. Стоит один прогон и ноль попыток.
