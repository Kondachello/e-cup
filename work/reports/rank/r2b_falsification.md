арифметики, а не модели.

то есть в сто раз сильнее, чем их публичные скоры. Это не спасение модели, это её опровержение:

## 3. Свободная охота: где машинка ЦЕЛА

Скептик обязан сказать и это — провал теста 2 не численный, а содержательный.

- **Формула правильная.** k_eff = tr[(G + lam·R)^-1 G] − 1 — это стандартные эффективные степени
  свободы гребня. Спектральный маршрут = прямому следу: 65.9884 против 65.9884 (разница 7.9e-09).
  При R = I без «−1» получается 66.968 — ровно каноническая df гребня. Согласовано.
- **R и G местами НЕ перепутаны.** `A = (G*S).T*S` с `S = 1/sqrt(r)` даёт ровно R^(−1/2) G R^(−1/2),
  и sum μ/(μ+lam) = tr[(G+lam·R)^-1 G]. Если бы перепутали (tr[(R+lam·G)^-1 R] − 1), вышло бы
  122.23 вместо 65.99 — такого нет.
- **Нормировка «−1» корректна.** Доля координаты свободного уровня в следе при рабочем lam =
  0.999989, вычитается ровно 1.0, ошибка 1.1e-05 — пренебрежимо.
- **Численная сборка G честная.** parts() против ядра quad_parts на спанах 25/72/123/163:
  max|ΔG| ≤ 6.3e-13 при масштабе G = 1.77 (отн. 3.6e-13), k_eff совпадает до 3 знаков. Самопроверка
  автора на спане 25 обобщается на рабочие спаны — вопреки опасению, катастрофического сокращения
  при сборке через грам-матрицу M = LLᵀ/N нет.
- **Знак в целом верен.** Корреляция k_eff и паблика по 10 витринам = **−0.892**: больше подогнано →
  лучше паблик. Машинка не мусор — она просто на порядок грубее той точности, которую требует тест 2.

## 4. Свободная охота: дефекты сверх обязательных тестов

1. **Вырожденный предел lam → ∞ даёт −1, а не 0.** Замерено: k(1e2) = 0.054, k(1e4) = −0.499,
   k(1e6) = −0.990, k(1e14) = −1.000. «−1» вычитается безусловно, поэтому эффективное число
   направлений становится ОТРИЦАТЕЛЬНЫМ. В рабочем диапазоне (lam ≤ 1 → k ≥ 3.5) безвредно,
   но заявленный вырожденный случай не выполняется.
2. **Вырожденный предел lam → 0 даёт 111.8 вместо rank(G) − 1 = 119.** Десять собственных чисел
   тонут в шумовом полу float64 (самое отрицательное −6.3e-13) и клипаются в ноль. На рабочем
   lam ≈ 3e-04 это не влияет (lam на 8 порядков выше шумового пола), но предел не тот.
3. **Доверительный интервал k_eff занижен в разы.** Заявленный для SHOW11 [94.8; 97.2] построен
   ТОЛЬКО по скобке lam (невязка ≤ 1.05·best). Он не покрывает ни выбор R (SHOW11: 96.0 канон /
   96.4 при I / 93.0 при diag(G)), ни выбор спана. Для пары SHOW9/SHOW10 честный разброс Δk —
   от 1.95 до 8.41. Скобку нельзя предъявлять как погрешность.
4. **Заголовочная таблица противоречит собственным логам.** Машинка ставит SHOW9 на спан 123,
   а SHOW10 — на спан 124, хотя `DOC` в её же коде фиксирует span = 123 для обеих. Спан выбран
   минимизацией невязки, то есть подогнан; на этом же спане 124 держится единственная проходящая
   конфигурация теста 2.
5. **Двойная подгонка реконструкции.** Для каждой витрины подбираются ДВА параметра (спан и lam)
   по самому файлу витрины. Для SHOW9 k_eff по спанам 115…123 гуляет 58.5…67.0, для SHOW10
   65.9…70.6. Реконструкция сама обладает степенями свободы, которые в её выходное число не
   заложены.
6. **Ключевые витрины рецептом не воспроизводятся.** SHOW_maxpub 16.8 % и SHOW2_aggr 12.4 % от ‖d‖
   (автор это признаёт); для них k_eff = 31.1 и 26.8 — не измерение, а проекция на чужой путь.
   SHOW5 9.6 %, SHOW8 6.5 %.
7. **Контрольная пара проходит — значит тест выполним.** SHOW3_maxpub / SHOW3b_safe: единственная
   пара, чей скрипт сборки реально лежит в репозитории (`make_show3.py`), один спан 72, два lam.
   |пред − набл| = **4.7e-05 ≤ 1e-04, ПРОЙДЕН**. Машинка проваливает тест ровно на той паре,
   которую назначил штаб. Порог не завышен и не невыполним.
