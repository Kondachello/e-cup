# Перепроверка закрытого направления «v8-дарители» против нового бленда — МЁРТВ ПОВТОРНО (22.08, ночь)

## Зачем перепроверяли
Тир v8 (дарители+пробуждения, 19 признаков) закрывался 19.08 об СТАРУЮ эпоху
(+0.0004 AUC в пуле против контроля равной ёмкости), причём **обучение тогда не
запускалось вовсе** — закрытие было по логистике в подгруппе. С тех пор: бленд
радикально сменил состав (kostya46_cal 0.246 + tfm3b 0.20 + gseq + lagd28, эталон
val 1.665647), вклад считается точной алгеброй (margin.py), и в реопте «мёртвые
поодиночке» модели (tfm3_stale28, hz_v1_pb) оживали при смене состава. Плюс
тестовое окно (14.02–15.03) накрывает 23.02 и разгон к 8.03 — «час дарителей»,
если сигнал жив.

## Протокол
Полноценное обучение обеих рук, чего при закрытии не делалось:

- **Пересборка тира**: build_features_v8.py, 20 срезов (14 train gap30 + 4 gap +
  VAL + TEST), 23 с. Календарь бит-в-бит совпал с задокументированным
  (9 мажорных событий, покрытие окон 0.335) — тир воспроизведён точно.
- **Рука v8** `twl_v8`: чемпионский конфиг (lgb tweedie-1.45-on-log, gap30,
  n_anchors 14, seed 42, USE_V2/V3/V4) + USE_V8 → 222 признака. 418 с.
- **Контроль равной ёмкости** `twl_v8cap`: тот же конфиг/сид/срезы + USE_V5CAP=19
  (19 ротированных ранг-колонок существующих признаков — ёмкость без информации)
  → тоже 222 признака. 175 с.
- Замеры margin.py / joint_gain.py --each об эталон = колонка `blend` пака
  (проверено: 1.665647).

## Вердикт: МЁРТВ ПОВТОРНО

Дарительский инкремент над равной ёмкостью существует и в новой эпохе
(+0.00016 val, +0.0021 AUC пула), но он **целиком внутри оболочки нового
бленда**: запас отрицателен у обеих рук, вклад по точной алгебре — ноль, NNLS
даёт вес 0.000. Модель С v8-тиром даже в целевом для тира пуле ранжирует хуже
самого бленда (0.6278 < 0.6336) — новый состав (gseq/секвенсы + kostya46) уже
покрывает эту зону лучше, чем табличный чемпион с дарительскими фичами.

Аргумент «час дарителей» (23.02+8.03 в тесте) не спасает: черта опровергнута
зеркальным тестом по специфичности (дельта отрицательна у ВСЕХ gf_* на срезах с
подарочным окном), а перенос диффузного (~0.55) применяется к вкладу, который
равен нулю — 0.55 × 0 = 0. GPU-спека не требуется: секвенс-трек (gseq) уже
представляет именно эту зону в бленде.
