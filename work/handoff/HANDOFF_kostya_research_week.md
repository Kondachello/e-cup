# Костя — НЕДЕЛЬНЫЙ РЕСЕРЧ, полностью независимая линия (дедлайн перенесён)

Костя, у тебя неделя карты и СВОЯ линия исследований: ни kevf, ни tfm4 не
трогаем (их ведут другие) — ни кода, ни чекпойнтов, ни тензоров. Всё ниже
строится с нуля на train.parquet, пересечений по артефактам нет. Четыре
программы + финал, по убыванию приоритета. Принцип недели: каждые сутки —
хотя бы один принятый/отклонённый вердикт.

Компас — что кампания ДОКАЗАЛА прямыми замерами о тест-окне:
живой сигнал — это **фаза личного цикла покупок** (+0.138), **свежие корзины
без покупки** (+0.196), **браузинг у спящих** (+0.372, сильнейший), **промо-
чувствительность, растущая с чеком** (наклон +0.61), **переоценка неверов,
особенно браузящих** (−0.31). Мёртвый сигнал — статичные профили (AOV, стаж,
каналы, моментум). Твои архитектуры должны уметь выражать первое.

## Программа 1 (дни 1–3): нейронный точечный процесс — НОВОЕ семейство

Модель интенсивности покупок per-user (нейро-Хоукс / neural TPP): история
событий юзера задаёт λ(t) покупок и распределение чека; прогноз = E[Σ трат за
30 дней] интегралом интенсивности. Почему это наш кандидат №1:
- интенсивность НАТИВНО выражает фазу цикла и затухание/разгон намерения —
  ровно то, что зонды показали живым, а окна признаков не выражают;
- это семейство ни разу не пробовалось (BG/NBD-фичи были, самостоятельной
  вероятностной модели не было) — максимальная декорреляция с пулом;
- у нас есть готовая инфраструктура таргетов и валидации (gap30, якоря).
План: v0 — простая параметрическая интенсивность с нейро-модуляцией истории
(GRU/MLP по последним K событиям на входе, экспоненциальные ядра), лосс —
правдоподобие точек покупок + регрессия log-чека; E[log1p(сумма)] — Монте-Карло
или квадратурой. v1 — добавить промо-календарь как внешний регрессор
интенсивности (даты ранов в отчётах holiday_cal). Приёмка ежедневно: калибровка
→ margin.pair_contribution против пула (порог интереса 0.0001, мечта 0.0003+).

## Программа 2 (дни 3–4): SSL-претрейн С НУЛЯ (свой транк, никаких чужих весов)

Собственное хранилище событий (свой скрипт по train.parquet, не чужие тензоры),
маскирование спанов 1–4 дня по всей истории включая бестаргетный хвост до
13.02, реконструкция каналов + Δt. Транк — любой твой (хоть тот же TPP-энкодер
из Программы 1 — тогда это её претрейн, красивая связка). Ворота: linear probe
на замороженном транке против случайной проекции; прошёл — файнтюн RMSLE-головы.

## Программа 3 (день 5): табличный трансформер (FT-Transformer/SAINT)

Быстрая программа: наши 203+ признака, attention-по-фичам вместо деревьев/MLP.
Никогда не пробовали; известен как местами сильнее GBDT на таких данных.
Готовые реализации допустимы при свободной лицензии (проверь и запиши). Два
сида, калибровка, pair_contribution. День — достаточно для вердикта.

## Программа 4 (день 6): дистилляция ансамбля в одну модель

Учитель = преды действующего бленда на всех якорях (соберу и выгружу тебе
одним parquet по первому запросу), ученик — одна сеть на признаках+событиях.
Двойная ценность: возможный член пула (дистиллят иногда обгоняет учителя за
счёт сглаживания) и готовый прод-аргумент для питча жюри («15 моделей → одна»).

## Программа 5 (день 7): масштабирование победителя

Лучшее из недели: 3 сида, среднее, калибровка, полный joint_gain, передача
test-предов — зонд оси и дозу в финальную сборку сделаем мы, слоты есть.

## Правила недели

1. Дампы каждые 1500 шагов / каждый час обучения; выгрузка стандартной
   тройкой ИМЯ_val/test.parquet + ИМЯ.json.
2. Каждому эксперименту — парный контроль (тот же сид, та же валидация gap30).
   Вердикты только через pair_contribution/joint_gain, не через сырой вал.
3. Отрицательный результат за сутки ценнее незамеренного «почти готово».
4. Провенанс в json рядом с чекпойнтом: конфиг, сид, команда, лицензии
   сторонних реализаций.
5. Живое ≥0.0003 — сразу в ветку, не жди конца недели.
