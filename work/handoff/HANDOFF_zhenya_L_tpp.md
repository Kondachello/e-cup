## L1 (к завтрашнему вечеру): метрика под точечный процесс

Костя строит нейро-TPP инженерно, на глаз. Дай ему математику:

1. **Правильный оценщик цели.** Метрика — RMSLE на S₃₀ = сумма трат за 30 дней.
   Модель даёт интенсивность λ(t) и распределение чека. Нужен вывод: как из
   (λ, чек) корректно получить E[log1p(S₃₀)] — не E[S₃₀] с логарифмом сверху
   (Йенсен, наш урок Н7!). Варианты: квадратура по распределению S₃₀,
   сэддл-пойнт, MC с контролем дисперсии; дай рецепт с порогами применимости
   и оценкой систематики каждого.
2. **Правильный лосс обучения.** Что оптимизировать в трейне, чтобы
   минимизировался итоговый RMSLE: прямое правдоподобие точек + отдельная
   голова E[log1p]? композитный лосс? Свяжи с нашей hurdle-доктриной (Р1):
   p·μ-структура — это вырожденный TPP, покажи, где TPP обязан выигрывать.
3. **Санити-набор**: 3-4 замкнутых теста (пуассоновский юзер, периодический
   юзер, юзер с промо-скачком), где ответ известен аналитически — Косте для
   отладки. Это час работы, а ловит 90% багов интеграции.

фаза и промо в интенсивности

1. **Идентифицируемость фазы**: при скольких покупках в истории личный цикл
   извлекаем? Байесовское смешение личного интервала с популяционным приором
   (иерархия: мало покупок → популяционный цикл, много → личный). Формула

2. **Промо-регрессор**: спецификация λ(t) = базовая(t)·exp(β_промо·1_ран(t) +

   правильно ловящая промо, должна ВОСПРОИЗВОДИТЬ эти сегментные сдвиги на
   вале без дозирования. Это готовый критерий качества TPP.

Твои n1–n22, a1–a6, b1–b2, k2/k4 — это 30+ скриптов с золотой математикой и
нулевой связностью. Собери пакет `work/doctrine/`:

- `transfer.py` (κ, w, w_p, fpc, локальная σ_u), `dose.py` (усадка, семейные
  приоры, джойнт с Грамом), `probes.py` (дизайн зонда, ценность V(q,τ),

- каждый закон = юнит-тест на исторических замерах (реестр 164 строк — готовый
  тестовый корпус: «w_p: наклон −0.2500±0.001 на 800 разрезах» и т.д.);
- README с формулами — фактически сжатая монография.

Это (а) страховка от ошибок в оставшихся расчётах, (б) артефакт для жюри
(«у нас библиотека управления неопределённостью, вот тесты»), (в) IP команды
после соревнования. K3-монография тогда ссылается на код, а не наоборот.

## L5 (в монографию, без дедлайна): теорема об извлекаемости

Формальная характеризация: какие функционалы скрытого теста извлекаемы
зондами в принципе (линейные по остатку — да; вторые моменты — нет; что
посередине?), и оптимальный дизайн эксперимента при бюджете N зондов. У нас
есть уникальный эмпирический материал: 60+ зондов с известными исходами.
Это глава, которая делает монографию статьёй, а не отчётом.
