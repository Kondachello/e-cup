# Kaggle-трек: событийный трансформер (kevf)

Зачем есть этот трек и почему именно событийное представление — в шапке
`kaggle_seq.py` и в `work/reports/kaggle_plan.md` (перебор направлений по ожидаемому
запасу). Коротко: это единственный живой класс (прогноз не является функцией 203
признаков), и представление, которого нет ни у табличного пула, ни у недельного
трансформера на Colab. Заодно снята замеренная проблема Colab: хранилище событий
0.6 ГБ живёт целиком на GPU, ввода-вывода в шаге обучения нет, GPU не простаивает.

## Железо и бюджет

- Kaggle: T4 x2 (две карты = два сида параллельно), квота 30 GPU-часов в неделю,
  сессия до 9 часов и не отбирается посреди работы.
- Одна сессия: сборка ~5–10 мин + два сида по ~4–6 ч параллельно = укладывается.
- P100 — запасной вариант: один процесс, те же команды без `--device`.

## Порядок работы (один раз)

1. Создать приватный Kaggle Dataset (например `ozon-ecup-t3`) из двух файлов:
   `train.parquet`, `sample_submit.csv` (лежат в корне репозитория). Через сайт
   (New Dataset -> Upload) или CLI:

   ```
   kaggle datasets create -p папка_с_двумя_файлами
   ```

2. Новый Notebook -> Accelerator: **GPU T4 x2** -> Add Input: свой датасет.

3. Первая ячейка — сам скрипт (вставить содержимое `kaggle_seq.py`):

   ```
   %%writefile kaggle_seq.py
   ...содержимое work/kaggle/kaggle_seq.py...
   ```

## Каждая сессия

Сначала убедиться, что датасет прикреплён (правая панель Add Input -> свой датасет ->
плюс; в /kaggle/input должна появиться папка с train.parquet и sample_submit.csv —
скрипт ищет файлы на глубине до трёх уровней и при неудаче печатает, что смонтировано).

Ячейка 2 — ТОЛЬКО сборка, и дождаться строки «хранилище готово» (~1-3 минуты):

```
!python kaggle_seq.py build
```

Ячейка 3 — обучение, два сида параллельно, по одному на карту. ВАЖНО: `!cmd &` на
Kaggle запрещён («Background processes not supported»), поэтому запуск только через
subprocess:

```python
import shlex, subprocess

def launch(name, seed, dev):
    cmd = f"python kaggle_seq.py train --name {name} --seed {seed} --device {dev}"
    return subprocess.Popen(shlex.split(cmd), stdout=open(f"{name}.log", "w"),
                            stderr=subprocess.STDOUT, start_new_session=True)

procs = [launch("kevf_s42", 42, "cuda:0"), launch("kevf_s1337", 1337, "cuda:1")]
print("pid:", [p.pid for p in procs])
```

Ячейка 4 — следить интерактивно (перезапускать по вкусу):

```python
!tail -n 3 kevf_s42.log kevf_s1337.log; ls -la out/ 2>/dev/null
```

(именно `-n 3`: сокращённую форму `-3` GNU tail принимает только с одним файлом)

Ячейка 5 — сторож: держит ноутбук занятым до конца обоих прогонов и раз в 10 минут
печатает хвосты логов. В интерактиве её МОЖНО запустить и уйти; в режиме
Save Version -> Save & Run All она ОБЯЗАТЕЛЬНА последней ячейкой, иначе батч-прогон
завершится сразу после запуска процессов и убьёт их:

```python
import time
while any(p.poll() is None for p in procs):
    time.sleep(600)
    for n in ("kevf_s42", "kevf_s1337"):
        print(n, open(f"{n}.log").read().strip().splitlines()[-1])
print("коды выхода:", [p.returncode for p in procs])
```

Про живучесть: интерактивная сессия может умереть при закрытой вкладке по idle-таймауту.
Для прогона «поставил и ушёл» надёжнее Save & Run All (батч, до 9 часов, вкладка не
нужна) — тогда out/*.parquet попадут в Output сохранённой версии.

Прогресс каждые `--eval-every` шагов печатает **калиброванный** (2-fold) скор — только
его и читать, сырой не печатается вовсе. Каждые `--dump-every` шагов в
`/kaggle/working/out/` перезаписываются `ИМЯ_val.parquet` и `ИМЯ_test.parquet`
(усреднение последних 5 выгрузок, val и test с одних весов) плюс `ИМЯ.json` с кривой
и контрольная точка `ИМЯ.ckpt` для продолжения (`--resume`).

Если OOM: `--batch 384` (или 256). Если сессия оборвалась: тот же train с `--resume`
(хранилище пересобрать: `build` детерминирован).

## Приёмка (локально)

Скачать из Output три файла каждого имени, положить parquet в `work/colab/out/`, затем:

```
POLARS_MAX_THREADS=3 .venv/bin/python work/colab/ingest.py --name kevf_s42
```

ingest посчитает калиброванный скор, ЗАПАС δ и вклад против действующего бленда.
Решение о `--copy` в пул — только по запасу, не по скору. Порог вклада 0.0003.

## Протокол (зашит в скрипт, не выключать)

- зазор 30 дней: последний обучающий якорь 2025-12-15, целевые окна не позже 2026-01-14;
- калибровка 2-fold побитово как `calibrate.py` (бины 24, порог 500, half от rng(0));
- val и test пишутся с ОДНИХ весов на одной сетке выгрузок и одинаково усредняются —
  ловушка «одинаковый val, разный test» исключена;
- цели считаются из сырого gmv, а не из квантованных каналов.
