# work_kostya — модель сегмента непокупателей (`kostya46`)

Крупнейший одиночный член бленда: вес **0.246** из 1.006. ~46% пользователей в целевом
окне не покупают, и это главная масса ошибки; модель обучается прицельно на этой части
задачи. Действующая калибровка и вклад в бленд считаются уже за пределами этого
каталога — `work/scripts/calibrate.py`, затем `work/scripts/err_corr.py`.

## Артефакты, которые лежат в git

- `preds/kostya46_val.parquet`, `preds/kostya46_test.parquet` — предсказания
  (`user_id`, `pred` в сыром GMV), 250 000 строк, `user_id` отсортирован.

Именно они подставляются в бленд: `inference.py` берёт тестовый прогноз из
`final_submission/models/preds_test/kostya46_test.parquet` (та же копия).

## Полное воспроизведение с нуля

```bash
python work_kostya/reproduce.py          # train.parquet -> preds_repro/*.parquet
python work_kostya/check_reproduce.py    # сверка preds_repro/ с preds/
KSMOKE=1 python work_kostya/reproduce.py # смоук: только проверка, что код работает
```

`reproduce.py` — единственная точка входа: она сама готовит данные (`prep_data.py`),
собирает недельные кубы (`cube.py` на границах 379 и 409), строит признаки
(`features.py`) и обучает все головы смеси. Промежуточные файлы кладутся в
`work_kostya/_build/` (переопределяется переменной `KWORK`), результат — в
`work_kostya/preds_repro/`.

Побочно `reproduce.py` пишет ещё пару файлов `kostya46shade_*` — тот же прогноз,
домноженный на P(явится|признаки). В бленд этот вариант не входит и канонической копии
для него в репозитории нет; `check_reproduce.py` сверяет только `kostya46`.

**Канон:** сиды m2 = 1..4, twlog = 1..2, m1 = 1; `KTHREADS=2`. При `lightgbm==4.7.0` и
двух потоках воспроизведение побитовое; при другом числе потоков появляется float-дрейф
порядка 1e-7, и сверку надо смотреть с допуском (`check_reproduce.py` уже проверяет
`max |Δ log1p(pred)| < 1e-6`).

**Зазор:** обучающие якоря ≤ 2025-12-11 для вал-модели (35 дней до вал-окна) и
≤ 2026-01-09 для тест-модели. Внешних данных нет, сиды фиксированы.

Окружение — `requirements.txt` (python 3.11).

## Как устроена смесь

Обучаются два конфига LightGBM, каждый двумя способами: прямой регрессией на
`log1p(GMV)` и разложением P(покупка) × величина. Поверх них — «лестница»: набор голов,
предсказывающих `P(log1p(y) > t)` на сетке порогов `t`, из которых матожидание
восстанавливается численным интегрированием (трапеции плюс хвост выше последнего
порога). Итог — фиксированная выпуклая комбинация:

```
v2  = 0.55·(0.4·direct₁ + 0.6·(p×size)₁) + 0.25·twlog₁ + 0.2·(0.5·direct₂ + 0.5·(p×size)₂)
mix = 0.6·v2 + 0.4·лестница        pred = expm1(max(mix, 0))
```

Веса смеси заморожены в `reproduce.py`, они не подбираются при прогоне.
